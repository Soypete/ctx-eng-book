# OpenIE Evaluation and RelVis

Open Information Extraction proposes relational tuples without requiring a domain schema in advance. Evaluation is difficult not because there is no schema at all, but because many surface forms and tuple boundaries can plausibly represent the same sentence.

## RelVis as an Error-Analysis Reference

[Schneider et al., 2017](https://arxiv.org/abs/1707.07499) assembled evaluation data and analyzed errors across several OpenIE systems, including binary and n-ary extractions. Its continuing value for this book is methodological: precision and recall summaries need error analysis that shows *how* a tuple failed.

Useful categories include omitted or incorrect arguments, relation errors, boundary and granularity mismatches, redundant extractions, and unsupported content. Preserve the source sentence beside each tuple so reviewers can adjudicate grounding rather than compare strings alone.

## Define Matching Before Scoring

OpenIE evaluation depends on matching policy. Strict lexical matching can reject equivalent extractions; permissive matching can accept a tuple that changes meaning. Version the normalizer and matching rules, report unmatched and disputed cases, and inspect precision-recall curves rather than one F1 score.

RelVis reflects particular datasets, languages, annotation choices, and systems from its publication period. It is not direct evidence that a current LLM extractor works in a private domain. Reproduce only the relevant construct, then add domain sentences, n-ary relations, modality, negation, attribution, temporality, and provenance requirements.

## Evaluate Promotion, Not Only Extraction

An OpenIE tuple is a candidate derived assertion. Production evaluation should continue through entity resolution, schema mapping, validation, authorization, storage, retrieval, and downstream use. Measure cost per accepted assertion, unsupported promotion, duplicate entities, qualifier loss, and impact on task outcomes.

RelVis demonstrates that systematic OpenIE error analysis is possible. Reliability comes from adapting that discipline to the actual assertion contract—not from treating an old benchmark score as production proof.
