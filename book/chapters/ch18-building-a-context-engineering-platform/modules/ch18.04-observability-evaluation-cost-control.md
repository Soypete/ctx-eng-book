# Observability, Evaluation, and Cost Control

A platform is production-ready when operators can detect, diagnose, contain, and learn from failures without reconstructing the system from anecdotes. Observability, evaluation, and cost control form one feedback loop.

The feedback loop covers all three layers: Lexicon asks whether the right authoritative and current sources were available; Semantics asks whether identity, relationships, and evidence were represented and interpreted correctly; Pragmatics asks whether the result was valid, authorized, affordable, and appropriate for its intended effect. These controls are platform capabilities that can be composed around many language processes. An agent loop may consume them, but it is neither required nor sufficient for a production context platform.

## Preserve a Run Manifest

Link task, identity and authorization decisions, workflow and state versions, prompt and model versions, retrieval candidates and admitted evidence, tool proposals and effects, budgets, traces, and terminal outcomes. Keep protected content in governed stores and reference it from telemetry. Version telemetry schemas and record sampling.

## Evaluate Every Boundary

Use deterministic tests for ingestion idempotency, policy enforcement, schemas, state transitions, retry classification, and tool postconditions. Use judged datasets and ablations for retrieval and model behavior. Use scenarios for missing evidence, conflicts, injection, stale policy, duplicate delivery, crashes, and ambiguous effects. Validate any model judge against trusted judgments.

Compare a candidate with a baseline on paired, versioned cases. Report uncertainty and important slices. Deploy through shadow evaluation or a guarded canary with rollback. Production outcomes refresh the failure taxonomy and regression suite under privacy controls.

## Govern Reliability and Spend Together

Define service indicators for successful terminal outcomes, evidence support, authorization violations, recovery, latency, and cost per success. Set consequence-aware objectives and failure budgets; do not trade a forbidden effect for improved average quality. Attribute tokens, retrieval, tools, serving, storage, review, and recovery to outcomes.

```text
observe -> diagnose -> reproduce -> change one boundary
        -> evaluate -> canary -> measure -> retain or roll back
```

## A Minimum Production Checklist

- Authoritative and derived state are distinguishable and versioned.
- Retrieval returns provenance, policy outcomes, and explicit failure classes.
- The model proposes; trusted software authorizes and commits.
- Workflow state survives retries and crashes without duplicate effects.
- Sensitive context is governed in traces, caches, indexes, and memory.
- Evaluation covers components, scenarios, behavioral outcomes, and regressions.
- Cost and latency are attributed to successful and failed outcomes.
- Every deployed component has an owner, SLO, migration path, and rollback.

Not every system needs a graph, vector index, long-term memory, agent loop, or local model. Every system does need explicit boundaries proportionate to its consequences. A production context platform is the smallest system that can supply sufficient authorized evidence, constrain action, recover safely, and prove that changes improve the outcome.
