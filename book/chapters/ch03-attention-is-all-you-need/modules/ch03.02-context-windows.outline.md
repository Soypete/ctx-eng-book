# Context Windows and Positional Limits

## Argument
The context window is an invocation-scoped token budget, not persistent memory. Position affects model utilization, but current evidence does not justify a universal recency-bias explanation.

## Why it matters (reliability goal)
The reliability question "what information can the model actually see?"
depends on window mechanics, but visibility is only the start of the
context engineering framework pipeline. Position and serialization expose
meaning through syntax; manifests, provenance, authority, state, and policy
make the working set governable.

## Beats

1. **Position Encoding Preserves Order** — evidence: existing prose + research/attention-is-all-you-need-notes.md
   - Without position encoding, "the dog bit the man" = "the man bit the dog"
   - The original transformer used sinusoidal encodings; later models use several position methods
   - Long-context utilization varies by model, task, content, and placement

2. **Context Windows Are Invocation-Scoped Working Sets** — evidence: existing prose
   - Published window capacities require dated documentation
   - Think of it as an invocation working set, not a linearly read tape
   - Prior state must be included or retrieved through a tool
   - A context manifest records included sources, authority, versions, scope, serialization, and omissions

3. **Why Context Is Expensive** — evidence: existing prose, ledger (context cost of composition)
   - API: per-token pricing, input + output billed
   - Self-hosted: TTFT scales with context, KV cache needs GB of GPU memory, throughput drops
   - The question isn't "what fits" but "what's the right signal-to-cost ratio?"

4. **Order Matters for Attention Weights** — evidence: existing prose
   - Poorly ordered context degrades even correct information
   - Ordering is a syntactic choice to test, not a substitute for semantic structure or pragmatic enforcement
   - The model reasons about sequence

5. **Sequence Position Is Not Event Time** — evidence: existing prose + Chapter 0
   - Position in the serialized input is distinct from event, source, retrieval, version, and authorization time
   - Preserve temporal metadata and freshness decisions in the context manifest
   - Do not infer recency, authority, or causal order from placement alone

## Conclusion to reach
The reader should understand that context windows are hard limits, not flexible
memory. What does not fit must be governed: retained, summarized with
provenance, retrieved later, or explicitly omitted. Position affects
utilization, while authority, state, and context manifests determine whether
the working set is reliable.
