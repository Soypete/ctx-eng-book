# Compaction, Attention, and the Scaffolding Tax

## Argument
Context engineering requires active management of what's in the window. Compaction strategies (summary, compression, hierarchical contexts) and scaffolding techniques optimize attention distribution—but every layer of scaffolding has a cost (the "scaffolding tax").

## Why it matters (reliability goal)
Tie to Pragmatics pillar: without active context management, attention scatters across irrelevant information. The scaffolding tax represents the gap between what transformers can do and what production systems demand they do.

## Beats

1. **Control What the Model Sees** — evidence: existing prose + research/attention-is-all-you-need-notes.md
   - The context window is your controlled input
   - Include, exclude, order, compress—all determine output

2. **More Input Is Not Automatically Better** — evidence: long-context empirical source needed
   - Distractors can degrade some models and tasks
   - Missing evidence cannot influence the invocation

3. **Context Windows Have Hard Limits** — evidence: existing prose
   - At some point something gets dropped
   - Decide what gets dropped before the model decides for you

4. **Cost Is Not Optional** — evidence: existing prose, ledger (context cost of composition), research/scaffolding-tax-ai-utah-talk.md
   - Per-token or GPU compute—context has real costs
   - Engineering for cost means intentional inclusion, not max token count

5. **Position Matters for Attention Relationships** — evidence: existing prose
   - The model reasons about sequence
   - Poorly organized context degrades even correct information

6. **The Scaffolding Tax** — evidence: research/scaffolding-tax-ai-utah-talk.md (strong evidence)
   - We continually ask transformers to perform tasks that belong to data platforms
   - When a model creates a summary, it must predict which information future attention will value—before those tasks exist
   - Discarding the source makes omitted information irrecoverable; retaining source and provenance enables rehydration
   - The transformer is no longer responsible for remembering everything (external systems take on that work)

7. **Compaction Policies** — evidence: manuscript engineering synthesis
   - Deterministic filtering, extractive selection, abstractive summary, hierarchical retrieval, and structured state
   - Summaries are derived artifacts rather than authoritative replacements
   - Test exception, chronology, attribution, revocation, and failed-attempt retention

## Conclusion to reach
The reader should treat compaction as a versioned state policy: preserve authoritative sources, attach provenance, test information loss, and keep only scaffolding whose measured reliability gain justifies its cost.
