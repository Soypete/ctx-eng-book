# Ranking, Reranking, and Query Planning

## Argument
A query plan defines task-relative rightness, required state, candidate routes, fusion, reranking, budgets, and stop conditions.

## Reliability goal
Make routing and ranking failures observable and prevent score or token competition from overriding authority.

## Sequence
1. Define rightness and show the query plan in Mermaid. 2. Connect the curriculum's dense/BM25/RRF/cross-encoder/multi-query ladder. 3. Separate generation, reranking, and selection. 4. Explain pairwise ranking and Bradley–Terry as attention allocation, not verification. 5. Govern duplicates, freshness, authority, and diversity. 6. Plan deadlines and budgets. 7. Test failure and compare baselines.
