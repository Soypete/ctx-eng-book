# ch09.05 Context Precision and Context Recall

## Measure the Boundary You Can Label

Precision and recall require relevance judgments. They do not measure whether data is true, whether a tool call was appropriate, or whether an answer was correct unless the evaluation explicitly labels those outcomes.

At document or passage level:

```text
precision = relevant retrieved items / retrieved items
recall = relevant retrieved items / relevant items in the judged corpus
```

Use ranking metrics such as precision at *k*, recall at *k*, mean reciprocal rank, or nDCG when position and graded relevance matter. State the judgment unit, cutoff, corpus snapshot, and task. A metric without those details is not reproducible.

## Context Precision Is a Useful Proposed View

Traditional retrieval can return a relevant document that contains one useful paragraph and twenty irrelevant pages. This book uses *context precision* for the fraction of included evidence units judged useful to the task:

```text
context precision = useful included evidence units / included evidence units
```

The evidence unit might be passages, structured fields, graph paths, or context blocks. Token-level precision sounds exact but is usually expensive and ambiguous to label. Choose a unit reviewers can judge consistently, retain inter-rater agreement, and report numerator and denominator.

Context precision is not an established universal metric and should not be collapsed into a weighted “context quality” score. Retrieval, authorization, freshness, source truth, tool selection, model use, and task success are different boundaries. A dashboard can show them together without pretending their percentages are mathematically interchangeable.

## Recall Needs a Bounded World

The denominator for open-world relevance is unknowable. Estimate recall against a bounded judged corpus, a set of competency questions, known required evidence, or pooled candidates from multiple retrieval systems plus review.

For a policy question, reviewers can identify the clauses required to support an answer. For a dependency question, a source snapshot can provide expected paths. For exploratory research, recall remains an estimate and should be reported as such.

Keep Chapter 7 hydration separate. Required-slot coverage asks whether declared context inputs were usable. Retrieval recall asks whether relevant evidence in the evaluation universe was found. A required search slot can be hydrated while its retriever has poor recall.

## Optimize Under a Context Budget

Adding candidates may improve recall and reduce precision. Removing candidates may reduce cost while deleting a necessary exception. The correct operating point depends on consequence and the model's ability to use the supplied evidence.

Evaluate a precision–recall curve under realistic token and latency budgets. Include the context assembler: chunk expansion, deduplication, reranking, and truncation can change quality after retrieval. Measure both candidates retrieved and evidence finally included.

High-consequence actions should treat required authoritative state as slots, not as relevance-ranked context. Exploratory tasks may accept lower precision for broader recall. Neither rule is universal; encode it in the task plan and test it.

## Build an End-to-End Evaluation Harness

For each representative task, record:

- authenticated principal and task class;
- corpus, source, index, and policy versions;
- required slots and judged relevant evidence;
- candidates from every retriever;
- fusion and reranking results;
- evidence included and excluded under budget;
- model answer with claim-to-source support;
- action outcome, abstention, or policy stop.

Then report boundary metrics:

- retrieval precision/recall and ranking quality;
- required-slot coverage;
- context precision at the chosen evidence unit;
- freshness and authorization violations;
- supported-claim and unsupported-claim rates;
- correct answer, correct abstention, or safe action rate;
- latency, tokens, and retrieval cost.

An empty response is not a context-precision proxy; it can result from model, policy, transport, or application failure. Instrument those outcomes separately. Likewise, a successful generation says nothing about whether the evidence supported it.

## Use Failure Injection and Ablation

Remove one retriever, stale an index, hide a required clause, duplicate a high-ranking chunk, inject an unauthorized candidate, and force a reranker timeout. Verify that metrics identify the affected boundary and that policy stops unsafe tasks.

Ablation answers the adoption question: did graph expansion, dense retrieval, or reranking improve the target outcome enough to justify cost and new failure modes? Track quality by task class rather than hiding regressions in a global average.

Reliable retrieval is not the highest similarity score or the largest context. It is a measured pipeline that supplies sufficient, authorized, current evidence within budget and knows when it did not. Chapter 10 builds on this evidence boundary by validating model outputs and actions against governed constraints.
