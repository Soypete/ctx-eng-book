# ch12.01 Small Composable Systems

## Composition Moves Complexity to Contracts

Production AI systems accumulate retrieval, policy, state, tools, model gateways, evaluation, and recovery. Splitting those concerns into components can make failures easier to locate—if the interfaces are explicit. Decomposition can also increase network hops, partial failure, version skew, and operational ownership.

The UNIX analogy is useful because it emphasizes focused programs and composition. The familiar maxims were articulated in McIlroy, Pinson, and Tague's 1978 UNIX foreword, while Ritchie and Thompson's [1974 system paper](https://www.nokia.com/bell-labs/about/dennis-m-ritchie/cacm.html) documented the operating system's simplicity and interfaces. The lesson is a design heuristic, not evidence that every AI component should be a process or consume text.

## Split at Enforceable Boundaries

A component earns separation when it has a coherent responsibility, independently testable contract, different scaling or security needs, or a failure that should be contained. Useful boundaries include:

- retrieval adapters that return typed candidates and provenance;
- policy enforcement that receives trusted identity and exact resources;
- model gateways that enforce budgets and record invocation versions;
- tool executors that validate and commit side effects;
- durable workflow state that survives retries and restarts.

Do not split vector, lexical, and graph retrieval merely because their algorithms differ if one team and one transaction boundary can operate them more reliably together. “One thing” means one coherent reason to change, not one function per service.

## Make Replacement a Testable Claim

Swappability requires more than matching method names. Two retrievers can return different score scales, provenance, authorization guarantees, latency, and empty-result semantics. Contracts should specify types, schema version, policy scope, deadlines, idempotency, errors, ordering, provenance, and observability.

Use contract tests and recorded fixtures. Replace a component in shadow mode, compare outputs and downstream task results, inject timeout and malformed responses, then verify rollback. A clean diagram does not prove loose coupling.

## Keep the Model Inside the System

The model is not “the filter” in a trusted sense. It is a probabilistic transformation stage. The surrounding pipeline owns source selection, authorization, validation, state, effects, and recovery. Compaction remains lossy, but that does not imply every summarization is irreversible if source events are retained and derived artifacts can be rebuilt.

Measure component failures, contract violations, end-to-end latency, retry amplification, version skew, and downstream reliability. Composition improves reliability when it creates enforceable boundaries and contained failures—not simply when a monolith becomes many boxes.
