# Task Workspaces and Secret Management

## Argument
A per-task workspace organizes bounded state and handles, while secrets remain inside the smallest trusted executor or broker boundary.

## Context engineering framework
- **Lexicon:** admit only scoped, authoritative inputs and evidence with provenance.
- **Semantics:** give workspace artifacts declared types, identifiers, schemas, and lifecycle states.
- **Pragmatics:** bind capabilities and secret use to an owner, purpose, policy, and controlled effect.

## Reliability goal
Prevent cross-task contamination, unsafe cleanup, resource exhaustion, and credential exposure.

## Sequence
1. define safe workspace layout. 2. govern lifecycle/ownership. 3. pass handles rather than secrets. 4. preserve backend enforcement. 5. test recovery and cleanup.

## Example
Workspace tree deliberately contains no model-readable secrets directory.
