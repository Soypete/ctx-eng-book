# AI as a Marketing Category

## Argument
“AI” is an overloaded product category that obscures component boundaries. Reliable systems require a capable model plus engineered data, state, retrieval, authorization, orchestration, and evaluation.

## Why it matters (reliability goal)
Tie to Pragmatics pillar: ambiguous terminology leads to solving the wrong problems. Each "AI failure" is actually a failure in infrastructure, retrieval, state, authorization, or evaluation.

## Beats

1. **The Marketing Shell Game** — evidence: existing prose
   - "AI" = math technique + product category + VC thesis simultaneously
   - Ambiguity serves vendors, liability for engineers

2. **Why Model Access Is Becoming Less Differentiating** — evidence: primary comparative evidence needed
   - [Sequeda et al., 2023](https://arxiv.org/2311.07509) — knowledge graphs boost LLM accuracy from 16% to 54%
   - [Hu et al., 2021](https://arxiv.org/abs/2106.09685) — LoRA enables parameter-efficient adaptation
   - Model rankings remain task- and evaluation-dependent; system layers still differentiate

3. **The Database Analogy** — evidence: existing prose
   - Database → commodity; data platform → differentiator
   - Model → commodity; context engineering platform → differentiator

## Conclusion to reach
The reader should treat prompt wording as one replaceable interface and invest in system knowledge encoded in retrieval, state, authorization, operations, and evaluation.
