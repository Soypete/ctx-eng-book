# The Production AI Stack

## Argument
The model sits inside a stack of hardware, inference, data, orchestration, and governance. Capability comes from the model; production reliability emerges from contracts and behavior across the complete stack.

## Why it matters (reliability goal)
Tie to Pragmatics pillar: context delivery determines whether the model can do its job. Model capability ≠ production reliability.

## Beats

1. **The Stack Layers** — evidence: existing prose
   - Hardware → Inference → Data → Orchestration → Governance
   - "Obsessing over the CPU while ignoring the query planner"

2. **Inference Cost Optimization** — evidence: primary serving benchmark needed
   - Serving choices change latency, throughput, memory, and cost
   - [Hu et al., 2021](https://arxiv.org/abs/2106.09685) supports LoRA adaptation claims, not the former 40% serving-cost claim

3. **Hybrid Retrieval** — evidence: ledger (Hybrid Retrieval Boosts Performance)
   - [Hsia et al., 2024](https://arxiv.org/2403.09040) — reader robustness to noise is key determinant of RAG stability
   - Vector search alone is insufficient

4. **The AI Generalist** — evidence: existing prose
   - Generalist value: velocity, prototyping
   - Generalist limitation: depth, reliability
   - Context engineering is the specialization that makes it reliable

5. **What Actually Determines Production Behavior** — evidence: existing prose + ledger (LLM Production Deployment Challenges)
   - [Arize AI](https://arize.com/llm-observability) — 53% plan to deploy, 43% cite accuracy/hallucinations as barriers

## Conclusion to reach
The reader should believe that context engineering—not prompt engineering—is the discipline that makes AI reliable in production.
