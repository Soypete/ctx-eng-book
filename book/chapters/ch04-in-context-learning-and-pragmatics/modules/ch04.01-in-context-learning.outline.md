# In-Context Learning

## Chapter-spine placement
This module is a technique for moving through **Lexicon → Semantics →
Pragmatics**: assemble relevant data and definitions, represent their meaning
in usable form, and state the purpose and acceptance criteria for the output.
Syntax is the representation layer, not a synonym for Semantics; prompt
engineering is one interface technique, not the definition of Pragmatics.

## Argument
Hidden, unconstrained inference makes failures difficult to reproduce. Context engineering exposes goals, assumptions, evidence, examples, and acceptance criteria so important ambiguity can be evaluated.

## Why it matters (reliability goal)
By exposing goals, constraints, examples, and evidence, a system makes
consequential pragmatic assumptions inspectable while preserving the lexical
and semantic context needed for search, extraction, classification,
summarization, recommendation, and workflow automation—not only agents.

## Beats

1. **Unmeasured Inference Creates Variance** — evidence: reliability evidence needed; Brown and Khattab support narrower model/program claims
   - Models infer from context; when context is ambiguous, inference produces unreliable outputs
   - Context engineering flips this: do inference work upfront, let model extract

2. **Invocation vs Workflow Context** — evidence: systems distinction in manuscript
   - Invocation context is fixed for one call but may be assembled dynamically
   - Workflow context arrives between calls through tools, retrieval, and events
   - MCP is one optional protocol, not a category of context

3. **Prompt Optimization as One Technique** — evidence: [DSPy compiler optimizes prompts](research/dspy-notes.md)
   - Prompt performance is measurable and optimizable
   - What to tune: instruction wording, example selection, order effects, constraint framing

4. **Domain Expansion** — evidence: [LLMs enabling novel entity extraction](research/knowledge-graphs/ie-ner.md)
   - LLMs adapt to new entity types without retraining via in-context learning
   - Multi-lingual extraction, domain-specific entities, rapid prototyping

## Conclusion to reach
The reader should expose consequential assumptions, version invocation inputs, trace runtime evidence, and evaluate residual model inference rather than pretending it can be eliminated.
