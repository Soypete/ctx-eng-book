# Examples, Instructions, and Structured Outputs

## Chapter-spine placement
These are implementation techniques for expressing and checking the
Pragmatics layer after relevant Lexicon and Semantics have been assembled.
Syntax means parseable form; Semantics means domain meaning; Pragmatics means
purpose, actor, and permissible consequence. No technique here replaces
retrieval, semantic validation, authorization, or evaluation.

## Argument
Context engineering reduces the output space through tool formatting and structured outputs — constraining what the model can produce to what the system can reliably parse.

## Why it matters (reliability goal)
Make task purpose and output contracts inspectable for extraction,
classification, summarization, recommendation, workflow automation, and agent
actions. Examples, instructions, and schemas reduce ambiguity but do not
guarantee meaning or safe use.

## Beats

1. **Few-Shot as Teaching** — evidence: optional [Tool use as few-shot](research/toolformer-notes.md), optional [DSPy few-shot selection](research/dspy-notes.md)
   - Good example: exact input format, expected output format, reasoning pattern
   - Bad example: ambiguous, complex, or wrong behavior
   - Evaluate examples on held-out cases; do not assume they reveal or teach faithful internal reasoning

2. **Tool Formatting** — evidence: [Tool call format training](research/toolformer-notes.md)
   - Models trained on specific tool call formats — need explicit instruction
   - Best practices: schema-first, discriminating boundary examples, explicit failure handling
   - Ambiguity → wrong function names, malformed arguments, non-existent tool calls

3. **Structured Outputs** — evidence: [NER evaluation metrics](research/knowledge-graphs/ie-ner.md)
   - Validation detects nonconformance; constrained decoding can enforce supported syntax but not semantic correctness
   - Patterns: schema prompting, grammar-based generation, generate/parse/validate with bounded recovery
   - Function calling as an optional structured-interface example, not an agent-only foundation

4. **Measuring Extraction Performance** — evidence: [NER precision/recall/F1](research/knowledge-graphs/ie-ner.md)
   - Same metrics apply: Precision, Recall, F1, Slot Error Rate
   - Makes prompt performance observable and optimizable

## Conclusion to reach
The reader should define an executable contract, validate syntax and semantics, enforce authority, and measure held-out task outcomes; schema validity alone is insufficient.
