# ch10.03 Provenance and Derived Context

## Provenance Is a Chain, Not a Citation String

To debug a context-driven failure, operators need to reconstruct what source state was selected, which policy permitted it, what transformations changed it, and what representation reached the model. A URL alone cannot provide that chain.

For a retrieved item, record a stable source locator, source and retrieval versions, effective and retrieval times, principal/purpose scope, authorization decision ID, query or operation fingerprint, transformations, and final context item ID. Redact secrets and avoid copying sensitive attributes into broadly accessible logs.

## Derived Context Inherits Restrictions

Summaries, extracted facts, resolved entities, graph edges, and model conclusions are derived artifacts. They should reference their parent items and transformation versions. Derivation does not shed purpose, retention, tenant, or disclosure restrictions. When parents have different policies, the child needs a rule at least as restrictive as required by its inputs and intended use.

```json
{
  "item_id": "ctx-44",
  "kind": "summary",
  "parents": ["ticket:18#p4", "order:91@v7"],
  "transform": "support-summary-v3",
  "policy_decision": "authz-771",
  "purpose": "resolve_support_case",
  "effective_at": "2026-08-06T12:00:00Z"
}
```

This is lineage, not proof. The source may be wrong, transformation lossy, or authorization decision misconfigured. Provenance makes those failures traceable.

## Design for Replay and Deletion

Capture enough deterministic metadata to rebuild an assembly when policy permits, while minimizing logged content. Use hashes and protected evidence stores when raw payload logging is unsafe. Propagate corrections, revocation, and deletion through derived artifacts and indexes; tombstones or lineage queries may be needed to find descendants.

Test multi-parent derivation, a deleted source, changed consent, a corrected record, a new summarizer, and an audit user who may inspect decision metadata but not underlying content. Measure lineage completeness, orphaned artifacts, replay success, deletion propagation, and unsupported claims whose evidence path is absent.

Provenance improves reliability by locating evidence and transformations. It does not replace validation, authorization, or source-quality judgment. Module 10.5 turns this chain into coverage measures after policy-aware user context is defined.
