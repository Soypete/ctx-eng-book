# ch10.05 Provenance Coverage Metrics

## Coverage Depends on Required Evidence

Provenance coverage asks whether context items carry the lineage fields required for their task and type. It measures whether the Lexicon can be audited, whether semantic transformations remain traceable, and whether pragmatic authorization evidence survived assembly. Measuring bytes with “some citation” is misleading: a large cited document can hide many unsupported claims, and a structured row may need an identifier and snapshot rather than a URL.

Define a provenance contract per context-item type. Examples:

- database record: source product, stable record key, snapshot/version, effective time;
- API result: service, operation, response/version identifier, retrieval time;
- document passage: document and revision, passage locator, publication/effective time;
- graph path: node/edge identifiers, path, dataset version, assertion sources;
- derived artifact: parent IDs, transformation version, policy decision, lifecycle.

Confidence is required only when the item represents uncertainty; an authoritative record need not invent a confidence score. Owner, authorization decision, and purpose are related governance fields but should remain distinguishable from data lineage.

## Measure by Item and Dimension

For a declared required field set:

```text
item provenance coverage = conforming included items / included items
field coverage(f) = included items with required field f / items requiring f
```

Report numerator, denominator, item type, policy version, and task class. A single average can conceal that every graph path lacks assertion sources while document passages are complete.

Also measure claim-support coverage for generated outputs: claims with a valid evidence path divided by claims that require external support. This needs claim segmentation and reviewed entailment; links alone do not count.

## Instrument the Assembly Manifest

Validate provenance before inclusion. Record missing-field outcomes and whether the item was excluded, degraded, or routed for review. Protect provenance metadata because source names, query fingerprints, paths, and decision attributes can themselves be sensitive.

Alert thresholds should follow consequence. Missing a publication date on optional background may reduce quality; executing an action with no policy or source version is a governance incident. Track regressions by adapter and transformation version.

Test lost passage offsets, stale graph versions, multi-parent summaries, redacted audit views, deletion, replay, and an apparently cited claim whose source does not support it. Measure conformance, lineage breaks, replay success, claim support, and deletion propagation.

Provenance coverage makes traceability measurable. It does not measure source truth, semantic correctness, authorization correctness, relevance, or final-answer correctness. Keeping those boundaries separate is what makes the metric useful.
