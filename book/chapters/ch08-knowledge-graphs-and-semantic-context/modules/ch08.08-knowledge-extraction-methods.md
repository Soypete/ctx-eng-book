# Knowledge Extraction Methods

## Choose a Method per Field, Not per Fashion

Knowledge-graph ingestion rarely needs one universal extractor. Dates in a controlled form, product codes in tickets, company names in contracts, and open-ended incident causes have different ambiguity, volume, and consequence. Select the cheapest inspectable method that meets the field's evaluated error budget.

## What Each Method Actually Contributes

| Method | Useful when | Common failure | Operational strength |
|---|---|---|---|
| deterministic parser or rule | format and vocabulary are stable | misses unexpected variation | explicit behavior and cheap regression tests |
| supervised tagger/classifier | labels are stable and annotated examples exist | domain and distribution shift | predictable throughput and measurable class performance |
| OpenIE | discovering candidate relations before a schema is settled | noisy, noncanonical tuples | broad exploration with source spans |
| language-model extraction | language varies and the schema can be supplied at runtime | unsupported additions, nondeterminism, cost | flexible candidate generation and rapid iteration |

These are tendencies, not universal precision/recall rankings. A weak rule can have low precision; a domain-trained classifier can outperform a general model; OpenIE can miss relations; a language model can fail on a simple repeated format. Benchmark representative data.

NER detects mentions and types; it does not resolve identity. OpenIE proposes surface relations; it does not create a domain ontology. Language models may combine several linguistic operations in one call, but the surrounding system still owns normalization, resolution, validation, provenance, and retries.

## Build a Cascaded Extractor

A practical design routes fields by difficulty:

1. parse deterministic identifiers, dates, and enumerations;
2. apply domain taggers or classifiers for stable entity types;
3. invoke a constrained model for ambiguous passages or complex events;
4. validate every candidate under the same versioned contract;
5. send consequential uncertainty to review;
6. retain source spans and method versions for replay.

Rules can validate some outputs, but “LLM extraction plus rules” is not automatically the best hybrid. The correct cascade depends on volume, latency, languages, review capacity, and the cost of false acceptance versus missed extraction.

## Evaluate the Pipeline, Not a Marketing Category

Create a reviewed corpus that represents source formats, rare entities, negation, modality, coreference, conflicting claims, and adversarial text. Measure field-level precision and recall, exact source support, identity errors, constraint rejection, abstention, latency, cost, review rate, and downstream question accuracy.

Run candidates in shadow mode before promotion. Compare versions on the same documents and inspect high-consequence differences. A lower aggregate F1 can still be the safer system if it abstains on authorization-sensitive relationships; a higher F1 can be unusable if it invents unsupported qualifiers.

Extraction methods generate proposals. Reliability comes from routing, evidence retention, common validation, and measured promotion policy. The next module defines that promotion boundary.
