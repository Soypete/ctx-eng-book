# ch08.10 Multilingual Extraction Is an Evaluation Problem

## One Endpoint Does Not Mean One Quality Level

A multilingual language model can reduce the number of separately deployed extraction systems. It does not make language-specific failure modes disappear. Quality varies by language, script, dialect, document type, domain vocabulary, prompt language, and model. Aggregate accuracy can conceal that the system works well for English contracts and fails on code-switched support tickets.

The reliable claim is modest: multilingual models create a useful shared baseline. Production readiness still requires representative evaluation and fallback policy for every supported language and consequential field.

## Separate Identity from Labels

Ontology identifiers should not depend on one display language. A stable identifier can have multiple labels, definitions, aliases, and transliterations:

```text
ex:locatedIn
  preferred label [en] "located in"
  preferred label [de] "befindet sich in"
  preferred label [ja] "位置する"
```

Language-neutral identifiers improve interoperability, but they do not align concepts automatically. Terms can differ in scope or carry legal and cultural distinctions that have no exact translation. Domain experts must review mappings that affect policy or decisions.

Preserve source-language text and passage offsets. Store normalized identifiers beside, not instead of, the original expression. This allows reviewers to inspect the evidence and lets improved extractors replay the source later.

## Choose a Route by Evidence

Possible routes include direct multilingual extraction, language-aware preprocessing, a specialized model, translation followed by extraction, or review. Translation may help a stronger extractor but can alter names, negation, modality, gender, dates, and domain terms. Direct extraction may preserve wording but perform poorly in a lower-resource language.

Route using measured performance for the document class, not a universal hierarchy. Language identification can itself be uncertain, especially for short or code-switched text, so permit multiple language tags or an unknown outcome. Do not let a detector's label silently select a pipeline that discards part of the input.

## Evaluate the Complete Semantic Path

Build reviewed sets for each supported language, script, and relevant language pair. Include transliteration, code-switching, locale-specific numbers and dates, ambiguous names, negation, modality, and culturally specific concepts.

Measure:

- entity and relation performance by type and language;
- source-entailment and unsupported-addition rates;
- cross-language entity-resolution errors;
- normalization of dates, units, and quantities;
- ontology mapping and untranslated-term rates;
- code-switch boundary failures;
- abstention and human-review yield;
- latency, cost, and downstream task outcomes.

Compare gaps explicitly. A deployment threshold can require minimum performance for each high-consequence relation rather than accepting a good global average. Languages below threshold need a safer fallback: restricted capabilities, translation with review, specialized processing, or no automated promotion.

## Monitor Drift and Corrections

Language use changes, domain terminology evolves, and model upgrades shift unevenly across languages. Record source language, detector version, extraction route, model and contract versions, and reviewer corrections. Shadow new versions across all supported slices rather than approving an upgrade on English alone.

Monitor correction rate, unresolved identity, invalid normalization, and promotion errors by slice. Give users and domain reviewers a way to correct labels and extracted facts without rewriting the source evidence. Propagate corrections through projections and indexes.

Multilingual extraction can expand access to structured context, but claiming it is “solved” would hide the people most likely to receive degraded behavior. Reliability comes from stable semantic identity, preserved source language, per-slice evaluation, bounded fallback, and observable correction—not from routing every language to one model.
