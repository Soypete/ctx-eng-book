# Instance Coverage and Ontology Population

## Argument

Graph population is measurable only against versioned source eligibility and competency questions; node counts and class diagrams do not establish task readiness.

## Reliability goal

Distinguish absent source-backed instances and paths from runtime retrieval failure so teams can repair the correct pipeline boundary.

## Sequence

1. Open with the education graph's missing classroom relationship.
2. Reject the dimensionally invalid instances/classes ratio.
3. Define class, source-record, relationship, and competency-question coverage.
4. Measure required paths rather than global node or edge volume.
5. Treat population as a rebuildable ingestion contract.
6. Make materialization versus federation an explicit tradeoff.
7. Separate graph population from Chapter 7 runtime hydration.
8. Validate missingness, correction, deletion, and replay.

## Evidence status

Coverage definitions are proposed engineering metrics in this book. Denominators must be explicit, and their usefulness should be evaluated against downstream outcomes. Linked-data completeness literature provides adjacent concepts but does not validate every metric formulation here.

## Corrections from draft

- `populated domain entities / modeled domain entities` mixed instances and classes and was removed.

- Slowly changing data does not universally belong in a graph, and high-volume data does not universally remain outside it.
- More instances or greater edge density does not by itself improve inference.
