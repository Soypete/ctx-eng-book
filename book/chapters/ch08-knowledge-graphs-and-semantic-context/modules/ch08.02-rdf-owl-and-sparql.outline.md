# RDF, OWL, SPARQL, and Shapes

## Argument

RDF data, ontology entailment, graph querying, and operational validation have distinct semantics; reliable systems assign each invariant to the mechanism that actually enforces it.

## Reliability goal

Prevent open-world inference, closed-world validation, identifiers, and storage products from being treated as interchangeable guarantees.

## Sequence

1. Assign jobs to RDF, RDFS, OWL, SPARQL, and SHACL.
2. Show identified RDF statements and their limits.
3. Explain entailment and the open-world assumption.
4. Add a SHACL shape for an operational acceptance boundary.
5. Query bounded graph patterns with SPARQL.
6. Compare RDF, property-graph, and relational choices without claiming equivalence.
7. Select the smallest stack that enforces the task invariant.

## Corrections from draft

- Not every RDF entity is a URI; RDF 1.1 uses IRIs, blank nodes, and literals under defined positions.
- OWL cardinality and RDFS domain/range do not behave like ordinary closed-world row validation.
- RDF and property graphs are not automatically lossless equivalents.
- A relational schema can implement graph-shaped data without becoming a graph database.
- Removed incorrect claims about PostgreSQL extensions and production usage.
