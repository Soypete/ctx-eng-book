# Persistent State and Retrieval

## Argument

Memory-like continuity depends on explicit lexical authority, semantic state,
pragmatic task boundaries, read and write paths, lifecycle governance, and
trajectory-level evaluation—not on mapping each memory label to a database
product.

## Context engineering framework

- **Lexicon:** preserve authoritative sources, provenance, scope, freshness,
  and acceptable derived copies.
- **Semantics:** derive and retrieve typed state with identity, relationships,
  validity, and uncertainty intact.
- **Pragmatics:** constrain retrieval and context assembly by actor, purpose,
  authorization, and workflow consequences.

## Reliability goal

Enable readers to design a state platform whose consistency gaps, authorization boundaries, transformations, and recovery behavior can be tested.

## Sequence

1. Select storage from access and lifecycle requirements.
2. Describe the write, semantic transformation, indexing, retrieval, policy,
   and context-assembly layers.
3. Govern retrieval before semantic ranking.
4. Treat model-generated memory writes as proposed state changes.
5. Evaluate supersession, revocation, deletion, rebuild, and replay as trajectories.

## Evidence

- [Orogat & Mansour, 2026](https://arxiv.org/abs/2605.26252) — state-trajectory framing and lifecycle operators.
- [Repository memory taxonomy](../../../../research/episodic-periodic-memory.md) — lifecycle controls and failure modes.

## Architecture example

Current-policy lookup versus semantic retrieval of prior support cases
demonstrates different lexical authority, semantic representation, and
pragmatic consistency requirements without prescribing a vendor.
