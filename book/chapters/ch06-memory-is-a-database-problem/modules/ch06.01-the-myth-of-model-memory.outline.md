# The Myth of Model Memory

## Argument

“Memory” is a continuity metaphor. Cross-invocation continuity is produced by
a governed lifecycle that moves from durable lexical sources, through
semantic state, to pragmatic task and workflow state around the model.

## Context spine

- **Lexicon:** identify the source records, entities, provenance, and
  authority that persist outside the model.
- **Semantics:** represent facts, relationships, validity, and uncertainty
  rather than treating retrieved messages as meaning by default.
- **Pragmatics:** bind that meaning to an actor, purpose, workflow, and
  enforceable action boundary.

## Reliability goal

Give engineers an inspectable fault model for memory: capture, identity, authority, write, indexing, retrieval, context assembly, model use, revision, and deletion.

## Sequence

1. Open with the apparent recall of a user preference.
2. Distinguish parameters, invocation context, caches, and durable application state.
3. Establish that retrieval is one stage in a larger memory lifecycle.
4. Map episodic evidence to Lexicon, semantic records to Semantics, and
   procedural/task state to Pragmatics; treat periodic work as maintenance.
5. Explain when ordinary indexes are sufficient and when explicit graph relationships help.
6. Apply the design to an authorized user-preference record and name useful reliability measures.

## Evidence

- [Orogat & Mansour, 2026](https://arxiv.org/abs/2605.26252) — agent memory as a governed, evolving data-management workload.
- [Repository memory taxonomy](../../../../research/episodic-periodic-memory.md) — episodic, semantic, procedural, maintenance, and failure-mode synthesis.
