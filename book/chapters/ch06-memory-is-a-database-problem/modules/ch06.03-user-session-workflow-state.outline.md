# User, Session, and Workflow State

## Argument

Reliable language systems separate durable lexical evidence, semantic state,
and pragmatic task state while also separating owner, lifetime, authority, and
recovery requirements. User, session, and workflow state cannot safely share
an undifferentiated “memory” lifecycle.

## Context engineering framework

- **Lexicon:** user and session observations, source events, and authoritative
  account records.
- **Semantics:** preferences, identities, relationships, and effective facts
  derived from those records.
- **Pragmatics:** session purpose, approvals, workflow checkpoints, tool
  commitments, and recovery transitions.

## Reliability goal

Let readers place each value behind the correct identity, consistency, expiration, and recovery boundary.

## Sequence

1. Define user, session, and workflow state in a comparison table, then place
   each record in the context engineering framework.
2. Explain why long-term is a retention horizon rather than an owner.
3. Govern inferred user preferences separately from authoritative settings.
4. Separate disposable session working state from consequential execution state.
5. Treat workflow state as the recovery contract for side effects.
6. Make promotions across state categories explicit and observable.

## Architecture example

An expense-report workflow shows stable execution identity, approval, idempotency, durable transitions, and crash recovery.
