# Harnesses and State Machines

## Argument
The harness owns system invariants and wraps probabilistic model decisions in explicit operational states and guarded transitions.

## Why it matters (reliability goal)
The model may propose; trusted code must enforce what remains true when the proposal is wrong.

## Beats

1. **The Harness Problem** — evidence: existing prose
   - Loop management, context assembly, tool execution, state persistence, observability, safety enforcement
   - Enforcement stays outside the model

2. **State Machines and Agent State** — evidence: existing prose + ledger (Generative Agents paper)
   - Operational states can be finite without model behavior being deterministic
   - Allowed transitions, terminal states, approval guards, and optimistic concurrency

3. **State Machine Design** — evidence: existing prose
   - Model proposes transitions; software validates and commits them
   - Surfaces hidden complexity: decision points, conditions, failure modes

## Conclusion to reach
The reader should model states that change authority, recovery, resource ownership, progress, or later semantics—and test the failure paths.
