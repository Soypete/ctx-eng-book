# ch07.02 Context Assembly Pipelines

## Concatenation Is Not a Pipeline

A naive context consumer fetches a profile, searches a few documents, appends recent messages, and concatenates everything above the user's request. It works until one source times out, a document contains instructions aimed at the model, or the combined results exceed the token budget. Then result order and string length become accidental policy.

A context assembly pipeline is the operational layer of Lexicon infrastructure. It makes those decisions explicit: it turns a task into a retrieval plan, executes identity-scoped requests, validates typed results and semantic roles, resolves authority and freshness, allocates a budget, and emits both a process-facing context and a machine-facing manifest.

The manifest matters as much as the prompt. It records what the model could have seen, what it actually saw, what was missing, and why the pipeline decided that inference was safe enough to attempt.

## Plan Before Retrieval

Source selection should follow the task. An order-status answer may require identity and fulfillment state, while prior support cases are optional evidence. A refund action additionally requires current policy, order eligibility, and authorization. “Query everything in parallel” wastes budget and increases disclosure.

A retrieval plan should specify:

- source and typed operation;
- principal, tenant, and purpose scope;
- required, conditional, or optional criticality;
- timeout and freshness limit;
- maximum records and tokens;
- authority and conflict rule;
- failure policy.

The host creates this plan from application policy and validated task fields. A model or other caller may help propose optional sources, but it should not be able to broaden its own identity scope or authority, reinterpret a source's semantic role, or reclassify a required policy source as optional.

## Represent Outcomes, Including Absence

Every source returns an outcome rather than an unlabelled string. At minimum, distinguish `ok`, `empty`, `denied`, `stale`, `timeout`, `invalid`, and `error`. An empty support history is valid information. A failed support query is not. Collapsing both into `[]` creates silent partial context.

The following standard-library Python sketch shows the boundary. The fetch functions stand in for adapters that enforce authorization and validate their responses.

```python
from dataclasses import dataclass
from enum import Enum
from typing import Any, Callable


class Status(str, Enum):
    OK = "ok"
    EMPTY = "empty"
    DENIED = "denied"
    STALE = "stale"
    TIMEOUT = "timeout"
    INVALID = "invalid"
    ERROR = "error"


@dataclass(frozen=True)
class SourceSpec:
    name: str
    required: bool
    token_budget: int
    fetch: Callable[[], Any]


@dataclass(frozen=True)
class SourceResult:
    name: str
    required: bool
    status: Status
    data: Any = None
    detail: str = ""


def retrieve(spec: SourceSpec) -> SourceResult:
    try:
        data = spec.fetch()
        status = Status.EMPTY if data in (None, [], {}) else Status.OK
        return SourceResult(spec.name, spec.required, status, data)
    except PermissionError as exc:
        return SourceResult(spec.name, spec.required, Status.DENIED, detail=str(exc))
    except TimeoutError as exc:
        return SourceResult(spec.name, spec.required, Status.TIMEOUT, detail=str(exc))
    except (TypeError, ValueError) as exc:
        return SourceResult(spec.name, spec.required, Status.INVALID, detail=str(exc))


def decision(results: list[SourceResult]) -> str:
    unavailable = {
        Status.DENIED, Status.STALE, Status.TIMEOUT, Status.INVALID, Status.ERROR
    }
    if any(result.required and result.status in unavailable for result in results):
        return "stop"
    if any(result.status in unavailable for result in results):
        return "degrade"
    return "proceed"
```

Production adapters should also normalize timestamps, source versions, provenance, and authorization decisions. Unexpected exceptions must become an observable `error` outcome at an outer boundary rather than disappearing. Concurrency and retries belong around idempotent reads, with a deadline for the whole assembly—not an independent timeout budget that can multiply without bound.

## Rank, Resolve, and Budget

Successful retrieval produces candidates, not a finished prompt. The assembler still has to:

1. remove candidates outside the active scope;
2. validate provenance and freshness;
3. resolve duplicates and known authority conflicts;
4. rank evidence for the specific task;
5. reserve space for policy, user input, tool schemas, and output;
6. truncate at semantic boundaries or retrieve smaller passages;
7. serialize each source as data, not as trusted instructions.

Budget allocation is policy. A fixed top-*k* per source lets six mediocre searches crowd out one required policy. Reserve budgets by role and criticality, then record exclusions. Summarization may save tokens, but it is a lossy transformation; retain source IDs and the summarizer version so the artifact can be audited or rebuilt.

Prompt-injection defense also belongs here. Retrieved documents are untrusted content even when they come from an internal index. Delimit them, label their source and authority, and prevent embedded text from changing tool permissions or system policy. The model is not the enforcement boundary.

## Emit Context and a Manifest

The model-facing output should communicate meaningful uncertainty without exposing secrets or raw infrastructure errors. The machine-facing manifest can be richer:

```json
{
  "assembly_id": "ctx-8f31",
  "decision": "degrade",
  "sources": [
    {"name": "identity", "required": true, "status": "ok", "included": true},
    {"name": "fulfillment", "required": true, "status": "ok", "included": true},
    {"name": "support_search", "required": false, "status": "timeout", "included": false}
  ],
  "budget": {"limit": 6000, "used": 3810},
  "policy_version": "order-status-v4"
}
```

Trace query parameters after secret redaction, source versions, latencies, result counts, ranking scores, transformation versions, token allocations, exclusions, and the final context hash. This makes replay possible without logging unrestricted sensitive payloads.

## Test the Assembly Boundary

Evaluate the pipeline independently of the model. Given a task fixture and source fixtures, assert which sources are selected, which records survive authorization and ranking, what order they appear in, how the budget is allocated, and which decision is emitted.

Then inject failures: a required timeout, an optional denial, stale policy, contradictory status, oversized document, malformed API payload, duplicate event, and an instruction embedded in retrieved text. The expected result is not always a prompt. Sometimes reliability means refusing to assemble one until a required source recovers or the user clarifies the task.

Context engineering is broader than query engineering, but the query pipeline is where distributed state becomes model-visible evidence. Making that pipeline typed, bounded, authorized, and replayable prevents infrastructure ambiguity from being handed to the model as if it were truth.
