# ch07.05 Public Data Sources: Wikipedia and the Web

## Public Retrieval Is a Different Trust Boundary

Internal data rarely contains all the background an agent needs. A support record may name a regulation without explaining it. A research workflow may need current publications. A developer agent may need a specification newer than its model parameters. Public retrieval can fill those gaps without copying the entire public web into an internal index.

It also introduces a different trust boundary. Search ranking is not source authority. A snippet is not the underlying document. A Wikipedia statement is not made primary by having a citation. A page can be stale, manipulated, ambiguous, or written to instruct an automated reader. Public text should enter the pipeline as attributed, untrusted evidence.

## Use Search for Discovery, Sources for Support

A web index is good at candidate discovery. It can find official documentation, papers, standards, incident reports, and relevant reporting across heterogeneous sites. The returned title, URL, snippet, and rank are routing metadata. They should not become the final factual context when the underlying page is available.

A reliable pattern is:

1. formulate a bounded query from the task;
2. restrict domains or source classes when authority is known;
3. retain the query, rank, URL, and retrieval time;
4. fetch the selected primary pages;
5. validate content type and extraction;
6. attach passage-level provenance;
7. compare sources when the claim is disputed or time-sensitive;
8. include only the passages needed for the task.

This separates discovery from evidence. It also makes failures visible: search found no candidate, the page was unavailable, extraction failed, or the page did not support the proposed claim.

## Wikipedia Is a Navigable Secondary Source

Wikipedia is useful because articles expose headings, internal links, revision history, and citations in a familiar document structure. Wikimedia APIs make pages and revisions retrievable, while Wikidata exposes structured statements, qualifiers, references, and value precision through its [data model](https://www.mediawiki.org/wiki/Wikibase/DataModel).

Internal links form a navigable graph, but calling Wikipedia “HATEOAS” overstates the analogy. HATEOAS is a constraint on hypermedia-driven application protocols. Wikipedia links support traversal among documents and entities; they do not by themselves define application state transitions or guarantee complete enumeration.

That distinction affects implementation. Following the France article and a few category links cannot reliably answer “all cities in France.” Category membership, list inclusion, administrative definitions, and coverage may differ. If completeness matters, use a source whose schema and coverage support the requirement, then measure missing and duplicate entities. Wikipedia can still help discover terminology and primary references.

Treat citations as routes to evidence. Follow the reference, verify that it supports the precise claim, record publication metadata, and prefer the primary source when available. Preserve the Wikipedia revision ID if article text itself is used so a later audit can reconstruct what the agent saw.

## Combine Public and Private Context Without Collapsing Authority

Private sources often govern account-specific truth. Public sources provide definitions, background, and external evidence. Keep those roles distinct in the assembly manifest.

For example, a benefits agent may retrieve an employee's plan from an authorized internal service and a public tax definition from the responsible government publication. A search result cannot override the employee's enrolled plan, and an internal note cannot rewrite the public regulation. The context serializer should label both source class and authority.

Public pages also create prompt-injection risk. Strip active content, treat page instructions as quoted data, constrain browsing tools, and never allow retrieved text to expand authorization or choose arbitrary side effects. Domain allowlists can reduce exposure for a known task, but they do not establish that every page on an allowed domain supports the claim.

## Evaluate Public Retrieval as a Pipeline

Use a claim-level evaluation set. For each task, record whether the system:

- found an appropriate source class;
- opened the underlying source rather than relying on a snippet;
- selected a passage that actually supports the claim;
- preserved publication and retrieval dates;
- distinguished primary from secondary evidence;
- represented disagreement or uncertainty;
- resisted instructions embedded in retrieved content;
- stayed within the task's source, latency, and context budgets.

Measure citation correctness, unsupported-claim rate, primary-source recovery, freshness violations, extraction failures, and public-content injection success. A generated answer with many links is not reliable if those links do not entail its claims.

Public retrieval improves reliability when it supplies current, attributable evidence the private system does not own. It reduces reliability when ranking is mistaken for truth or arbitrary web text is allowed to become policy. The engineering principle is the same as elsewhere in this chapter: source purpose and authority must survive assembly.
