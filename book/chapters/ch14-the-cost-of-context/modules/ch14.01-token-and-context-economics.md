# Token and Context Economics

Context is not free, but minimizing tokens is not the objective. The objective is the cheapest system that meets a defined reliability target. Removing evidence can lower the invoice while increasing retries, escalations, and incorrect actions. Adding everything can raise cost and latency while making the relevant evidence harder to use.

## Price the Successful Outcome

Provider prices and model limits change. Keep them in configuration rather than prose, and calculate cost from the workload actually observed:

```text
run_cost = input_tokens * input_rate
         + output_tokens * output_rate
         + retrieval_cost
         + tool_cost
         + compute_cost
         + storage_cost
         + review_and_recovery_cost

cost_per_success = total_run_cost / successful_terminal_outcomes
```

The second equation matters more. A cheap first attempt that repeatedly fails can cost more per completed task than an expensive attempt with the required evidence. Segment the result by task type and outcome; an aggregate average can hide a costly failure tail.

## Treat the Window as an Admission Boundary

A model’s maximum context window is capacity, not a target. Before invocation, the assembler should reserve output space and allocate the remaining budget among instructions, task state, retrieved evidence, tool definitions, and recent interaction history. Each item needs a reason for admission and a compaction or rejection policy.

Silent truncation is unsafe because it changes the task without changing the request. Prefer deterministic policies: preserve governing instructions and required evidence, compact only content whose loss has been evaluated, and fail explicitly when mandatory inputs do not fit. A summary is derived state, not a lossless replacement; retain provenance to its source and test it on decisions that depend on omitted detail.

The useful question is not “How much context can this model accept?” It is “Which minimum evidence set lets this task meet its outcome threshold, and what happens when that set does not fit?”

## Model the Marginal Value of Context

More context can help, hurt, or do nothing. Evaluate candidate context policies on representative tasks by varying retrieved items, demonstrations, history, and tool output. Track task success, unsupported claims, authorization violations, latency, and cost. A smaller policy wins only when it preserves the required outcome distribution.

Token counters are model-specific, so enforce budgets with the tokenizer or estimator associated with the deployed model and leave safety margin for estimation error. Record the pricing/version configuration with each cost observation. This turns a changing vendor price into reproducible operational data rather than a book claim that expires.
