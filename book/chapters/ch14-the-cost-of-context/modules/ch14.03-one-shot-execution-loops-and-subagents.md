# One-Shot Execution, Loops, and Subagents

One model call has a simple cost shape, but it is not automatically the cheapest reliable design. A bounded second call that verifies evidence may prevent an expensive incorrect action. A loop that exists only because state and validation are implicit usually adds cost without earning reliability.

## Compare Whole Workflows

Estimate the expected work, not a multiple of model-call price:

```text
expected_run_cost = sum(step_cost * expected_step_executions)
                  + expected_recovery_cost
                  + expected_human_review_cost
```

A loop changes context size, tool use, cache behavior, and failure probability at each iteration. Measure the distribution of iterations and identify what observable progress earns another attempt. Batch independent records only when the model and tool contracts preserve per-record identity, authorization, error isolation, and output validation.

One-shot execution fits bounded transformations with sufficient input and a testable output. Iteration earns its cost when an observation changes the next decision: a compiler error guides a repair, missing required evidence triggers a different retrieval path, or validation identifies a specific defect. Chapter 13’s progress and terminal-state controls still apply.

## Delegation Is a Parallel Workflow

A subagent duplicates some instructions, context assembly, model use, tools, and trace state. Parallel delegation may reduce wall-clock latency while increasing total compute and coordination failures. It is justified when work can be partitioned with explicit inputs, independently validated outputs, and a merge rule that is cheaper or more reliable than one shared context.

Budget the full tree: maximum depth, fan-out, tokens, tools, time, and external effects. Propagate authorization by attenuation rather than copying the parent’s authority. Record which child produced each claim or artifact. If several children return conflicting results, the parent needs an evidence-based reconciliation policy rather than another unconstrained vote.

## Memory Is an Operational Cost

Separate model-serving memory, attention/cache memory, retrieval-index memory, and durable workflow state. Parameter count alone does not determine serving memory: numerical precision, quantization, architecture, runtime overhead, concurrency, and sequence length all matter. Measure the deployed configuration instead of relying on a universal bytes-per-parameter rule.

Capacity failures are reliability failures. When concurrency increases, a system may queue, evict caches, spill an index to slower storage, or terminate workers. Load tests should vary context length and concurrency together, then report throughput, tail latency, memory high-water marks, and failed allocations.

Choose one shot, loops, or delegation from outcome measurements. Fewer calls are preferable when they preserve reliability; extra calls are justified only by a measurable reduction in failure or recovery cost.
