# Local Models and Model Routing

Running a model locally removes a provider invoice, not the cost of inference. Hardware acquisition or rental, energy, idle capacity, operations, upgrades, observability, and incident response remain. An API transfers part of that burden and introduces price, availability, data-governance, and dependency tradeoffs.

## Compare Total Cost Under Load

Benchmark candidate deployments on the actual workload: input and output lengths, concurrency, latency objective, availability requirement, regions, privacy controls, and task-quality threshold. Compare total cost per successful outcome rather than per-token price. Low utilization can make owned capacity expensive; steady high utilization can improve its economics. Neither conclusion is universal.

Smaller models are not categorically sufficient for classification or extraction, and frontier models are not categorically required for planning. Capability is a measured property of a model, prompt, schema, and task distribution. Evaluate important slices, malformed inputs, abstention, and downstream effects.

## Route With Observable Policy

A router predicts which route can satisfy the task at lower expected cost. Its inputs may include task type, risk, language, context size, required tools, and prior validation outcomes. The trusted host still enforces data residency and authorization; routing must not leak protected context to an ineligible endpoint.

Use a cascade when a cheaper route can produce an output with a reliable acceptance test. If the test fails, escalate with the original evidence and recorded failure rather than silently replacing the result. A confidence number from the same model is not sufficient unless calibrated for this decision.

Routing creates its own failure modes: misclassification, distribution shift, duplicated spend during escalation, cold-start latency, and inconsistent behavior across models. Compare it with a single-model baseline. Track quality and violations by route, escalation rate, routing regret, tail latency, and total cost per success.

The cheapest reliable solution is conditional: it meets explicit outcome, security, and latency thresholds at the lowest expected lifecycle cost. Model routing is useful only when those thresholds and costs are observable.
