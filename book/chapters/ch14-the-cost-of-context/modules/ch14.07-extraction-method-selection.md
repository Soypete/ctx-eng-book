# Extraction Method Selection: Rules, Models, and LLMs

Method selection is not a contest between old and new techniques. It is a routing problem over assertion types. A document can contain deterministic fields, ambiguous language, and relationships requiring domain interpretation. Sending all three through one extractor couples their cost and failure modes.

## Start With the Assertion Contract

Specify the source span, output schema, allowed labels, qualifiers, provenance, abstention behavior, and downstream consequence. Then establish the simplest credible baseline:

- a parser for an actual structured format;
- rules for stable, locally testable patterns;
- a trained model for a repeated statistical labeling task;
- an LLM for ambiguous or changing tasks where its evaluated quality earns the cost; or
- human review where the consequence exceeds automated confidence.

Rules are not exact merely because they are deterministic: format drift and overlapping patterns create systematic errors. LLMs are not appropriate merely because text is unstructured. Specialized models are not cheap if labels and maintenance dominate the workload.

## Route Uncertainty, Then Validate

A hybrid pipeline should not mean “run everything and choose whatever agrees.” It should expose why an item takes a route:

```text
parse source -> deterministic extraction
             -> specialized model
             -> LLM proposal
             -> human review
                     |
              shared validation
                     |
             versioned promotion
```

Validate syntax, ontology membership, source grounding, cardinality, temporal rules, and entity identity as separate checks. Agreement between two methods can be useful evidence but is not proof when they share training data, prompts, or upstream parsing errors.

## Test the Router

Evaluate each route and the router that selects it. Track coverage, precision and recall by assertion type, abstentions, review rate, latency, cost per accepted assertion, and downstream task impact. Include format changes and adversarial or malformed inputs. Compare the hybrid against single-method baselines; routing complexity must earn its maintenance cost.

Extraction does not need abstract perfection. It needs explicit error tolerances tied to consequences. A date shown for search ranking and a date used to release funds do not have the same acceptance policy. The cheapest method is the least expensive route that meets the relevant contract—and fails visibly when it cannot.
