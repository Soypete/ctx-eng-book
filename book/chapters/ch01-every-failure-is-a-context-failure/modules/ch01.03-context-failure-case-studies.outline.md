# Context Failure Case Studies

## Argument
Production-style scenarios show how missing exit criteria, unenforced permissions, unmeasured context, stale data, and authorization drift appear at concrete system boundaries.

## Why it matters (reliability goal)
Tie to all pillars: demonstrates that abstract failures manifest concretely in production.

## Beats

1. **Production Debugging Loop** — evidence: existing prose
   - Failure: 47 tool calls, no exit criteria
   - Fix: add confidence thresholds, tool call limits to context

2. **Customer Data Exposure** — evidence: ledger (prompt injection, capability-based access)
   - Failure: prompt-based permission, no structural enforcement
   - Fix: capability-based access with database enforcement

3. **$47,000 Context Bill** — evidence: ledger (context precision, cost of composition)
   - Failure: no budget controls, no retrieval limits
   - Fix: context budget at each stage (search, assembly, prompt)

4. **Stale Context Poisoning** — evidence: existing prose (temporal dimension)
   - Failure: 24-hour-old cached context
   - Fix: freshness metadata, staleness requirements

5. **Multi-Agent Authorization Drift** — evidence: ledger (agent authorization failure modes)
   - Failure: agents forwarding data beyond their permissions
   - Fix: capability verification on inter-agent calls

## Conclusion to reach
The reader should be able to locate each failure at an enforceable boundary and name the telemetry that would prove an architectural fix worked.
