# Missing State and Constraints

## Argument
Loops, permission violations, and cost overruns often expose missing workflow state, boundaries, budgets, or exit criteria; reliable systems enforce those constraints outside the model. Distinguish episodic, semantic, and working state before deciding what must persist or enter the prompt.

## Why it matters (reliability goal)
Tie to the context engineering framework: preserve the relevant Lexicon data and workflow state, make its Semantics explicit, and enforce through Pragmatics who may use it and what may happen next.

## Beats

1. **State Has Three Jobs** — evidence: curriculum module 10
   - Episodic state records what happened; semantic state stores current facts; working state is this turn's bounded context
   - Keep the trusted root set while trimming, summarizing, superseding, or archiving other material

2. **Workflow Loops Are Missing Exit Criteria** — evidence: existing prose and module 03 trace
   - Agents and other automated workflows don't know when to stop because success criteria weren't in context
   - Column name misspellings, multi-step dependencies → workaround loops
   - Terminal outcomes include answer, clarification, decline, missing evidence/permission, and exhausted budget

3. **Permission Failures Are Unconstrained Context** — evidence: ledger (prompt injection framework, capability-based access)
   - Prompt-based permissions inherit user credentials → prompt injection vulnerability
   - Fix: structural authorization, not prompt instructions

4. **Cost Overruns Are Unmeasured Context** — evidence: ledger (context precision, context cost of composition)
   - No budget controls → unlimited token consumption, redundant calls
   - Compaction failures: how to shorten context without losing relevance

## Conclusion to reach
The reader should believe that agents need structural constraints (state, permissions, budgets) encoded in the system, not in prompts.
