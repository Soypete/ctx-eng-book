# Personalization Failures as Missing Context

## Argument
Personalization failures occur when the system lacks user-specific context—preferences, history, permissions, or constraints that define what the model should customize.

## Why it matters (reliability goal)
Tie to the context engineering framework: preserve user state and source authority as Lexicon, represent preferences and identity through Semantics, and constrain personalization through Pragmatics to the authorized task and purpose.

   - Diagram: authenticated principal, task, preferences, policy, freshness, and task-scoped context
   - Preserve preference authority, provenance, freshness, and correction signals

2. **Missing User Preferences** — evidence: queued personalization surveys; review required before citation
   - Failure: model gives generic responses instead of user-specific

3. **Wrong User Context** — evidence: queued personalization surveys; review required before citation
   - Failure: model uses another user's context (data leakage via personalization)
   - Context gap: user identity not bound to context scope

4. **Stale Personalization** — evidence: existing prose (ch01.03 stale context case study)
   - Failure: preferences changed but model uses old context
   - Context gap: no freshness tracking for user state
   - Diagram: changed preference, invalidation failure, stale output

5. **Over-Scoped Personalization** — evidence: ledger (authorization failure modes)
   - Failure: model accesses user data it shouldn't (personalization as attack vector)
   - Context gap: personalization context not constrained by permissions

## Conclusion to reach
Personalization requires structural context (user identity, preferences, permissions, freshness) that's assembled at query time—not stored in the model.
