# Missing and Incorrect Information

## Argument
Treat context failure as the first production diagnostic: many unsupported outputs and wrong tool choices trace to missing, incorrect, irrelevant, or unconstrained information, while controlled residual failures may reveal model limits. Separate source, retrieval, and generation failures before choosing a repair.

## Why it matters (reliability goal)
Tie to the context engineering framework: Lexicon establishes what information and authority exist, Semantics defines what they mean, and Pragmatics constrains what the system may produce or do with them.

## Beats

1. **The Demo-to-Production Gap** — evidence: existing prose (the demo constrained outcomes, production doesn't)
   - Establish that demos limit scope; real-world has unbounded inputs

2. **Three Gates Before Blaming Generation** — evidence: curriculum's source/retrieval/generation split and tool trace
   - Distinguish absent source data, retrieval misses, and generation failures
   - A tool contract exposes capability but does not prove correct selection or successful execution

3. **Missing Context Is One Cause of Hallucination** — evidence: existing prose; primary-source gap marked
   - Missing, stale, contradictory, or poisoned evidence can produce unsupported answers
   - Semantics, pragmatics, and evidence reduce avoidable error but do not guarantee truth

4. **Wrong Tool Calls Are Missing Context** — evidence: ledger (dangerous retrieval, context-to-execution integrity)
   - Agents retrieve without direction → incorrect assumptions proliferate
   - Auto-generated tools without scoped purposes → selection failures

## Conclusion to reach
The reader should inspect the context and execution path before blaming the model, then use controlled evaluation to distinguish system defects from model-capability limits.
