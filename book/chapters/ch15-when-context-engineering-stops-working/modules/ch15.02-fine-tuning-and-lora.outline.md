# Fine-Tuning and LoRA

## Argument
Fine-tuning and LoRA are viable only when a stable behavior, representative training data, and held-out system evaluation justify a harder-to-inspect model artifact.

## Beats
1. Compare full adaptation, parameter-efficient adaptation, and no training.
2. Scope LoRA paper results to its evaluated settings.
3. Build provenance-bearing data and leakage-resistant splits.
4. Evaluate the full adapted system and deploy with rollback.

## Reliability takeaway
The context-engineering specification becomes the training and evaluation contract.
