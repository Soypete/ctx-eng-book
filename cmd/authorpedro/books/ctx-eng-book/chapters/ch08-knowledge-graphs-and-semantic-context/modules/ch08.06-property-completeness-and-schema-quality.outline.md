# Property Completeness and Schema Quality

## Argument
The precision of an ontology's properties determines how much reasoning the knowledge graph can support.

## Why it matters
A "Person" entity with only an "employer" property enables less inference than one with employer, education, nationality, advisor. Property completeness directly impacts downstream AI reliability.

## Beats

1. **Ontology precision vs entity precision** — evidence: kg-quality-metrics-notes
   - Precision in knowledge graphs = how well the ontology represents concepts
   - Poor: "Employee" — one class for all employment relationships
   - Better: "Faculty Member" → "Adjunct Professor", "Research Professor" — fine-grained types
   - This enables richer reasoning

2. **Property completeness defined** — evidence: kg-quality-metrics-notes
   - Property Completeness = Present properties / Expected properties per entity type
   - Example: Person entity has 4 expected properties (employer, education, nationality, advisor)
   - If only employer exists → 25% property completeness
   - Low completeness → degraded inference quality

3. **Measuring schema quality** — evidence: GAP (needs research)
   - Property fill rate by entity class
   - Missing property analysis
   - Optional vs required properties
   - Property coherence (are related properties present together?)

4. **The completeness-inference relationship** — evidence: GAP
   - How does property completeness predict inference quality?
   - Hypothesis: more properties = more traversal paths = better reasoning
   - Need to validate with experiments

5. **Improving property completeness** — evidence: GAP
   - Data ingestion improvements
   - Ontology refinement
   - Derived properties (computed from others)
   - External data enrichment

## Conclusion to reach
Property completeness is a design-time quality metric for knowledge graphs. Teams should measure expected properties per entity type, track fill rates, and treat low completeness as a schema quality issue that degrades AI inference.
