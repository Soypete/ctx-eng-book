# RDF, OWL, and SPARQL

## Argument
RDF, OWL, and SPARQL are foundational semantic web standards that provide global identity, formal reasoning, and query capability. They represent the mature, principled approach to knowledge representation—though production systems often use subsets.

## Why it matters (reliability goal)
Tie to Systems pillar: standards provide interoperability, auditability, and tooling ecosystem. RDF gives global identity, OWL enables formal reasoning, SPARQL provides declarative queries.

## Beats

1. **RDF as Foundation** — evidence: ledger (RDF W3C Standard)
   - Triples: subject-predicate-object
   - URIs: global identity across systems
   - RDFS: classes, properties, domain/range constraints

2. **OWL Expressivity** — evidence: ledger (OWL 2 W3C Standard)
   - Cardinality constraints: "every vendor has at least one product"
   - Property characteristics: transitive, symmetric, functional
   - Class relationships: equivalent, disjoint, subclass
   - OWL reasoners compute logical closure

3. **SPARQL Query Language** — evidence: ledger (SPARQL 1.1 W3C Standard)
   - Pattern matching over triples, not full-text search
   - Filters, constraints, and result projections
   - "Find all vendors who supply products in category X"

4. **Property Graphs vs RDF** — evidence: ledger (Amazon Neptune multi-model)
   - Property graphs: nodes/edges carry key-value properties
   - Both represent same information—systems decision, not semantic
   - Neo4j (property graph), GraphDB (RDF), Neptune (both)

5. **3NF as Graph Semantics** — evidence: existing prose
   - Foreign keys encode relationships
   - Join tables encode many-to-many edges
   - PostgreSQL + Apache AGE provides SPARQL over relational
   - Graph semantics are modeling choice, not product choice

## Conclusion to reach
The reader should understand that RDF/OWL/SPARQL are mature standards with different tradeoffs than modern property graphs—and that you may not need a graph database to get graph semantics.
