# Ontology-Guided Information Extraction

## The Extraction Challenge

Information extraction (IE) transforms unstructured text into structured knowledge. Without guidance, IE systems produce noisy, inconsistent, or irrelevant output. Ontology-guided extraction solves this by constraining what can be extracted to what the knowledge graph schema allows.

The research makes this clear: "Unlike NER, ontologies are foundational for RE because it is not always clear what the event is without the constraints of the ontology." [relation-extraction research]

This enables a "shift left" motion: move semantics and knowledge work earlier (design-time), define the ontology in configuration, and keep data contracts clean. [relation-extraction research]

## How Ontologies Guide Extraction

The ontology provides three constraints:

1. **Entity types** — What entity classes are valid? The extraction must classify entities into ontology classes (Person, Organization, Product, etc.). Out-of-scope entities are rejected.

2. **Relationship types** — What relationships are valid? The extraction must use only defined relationship types (supplies, manufactures, owns). Novel relationships are flagged for review.

3. **Cardinality and constraints** — How many? The extraction must respect constraints (every vendor has at least one product, each order has exactly one customer).

## The Extraction Pipeline

Ontology-guided extraction flows through stages:

1. **NER** — Identify mentions of entity types defined in the ontology
2. **Entity typing** — Classify each mention into the correct ontology class
3. **Relation extraction** — Identify relationships between typed entities
4. **Constraint validation** — Reject extractions that violate ontology rules
5. **Canonicalization** — Map extracted entities to canonical graph nodes

## LLM-Based Extraction with Ontology Guidance

LLMs transform the extraction landscape. "With LLMs, IE is knowledge distillation—extracting and structuring knowledge that exists in the LLM's training data into an explicit knowledge graph." [knowledge graph book research]

LLMs can also "identify entities that don't match predefined categories. Can extract novel entity types based on context and domain knowledge. Given an ontology, LLMs can classify extracted entities into the correct concept classes using in-context learning." [knowledge graph book research]

The pattern: provide the ontology as context, ask the LLM to extract only what's defined, validate output against constraints.

## Validation Guardrails

The ontology doesn't just guide extraction—it validates output:

- Query the graph to ensure proposed outputs are consistent with known facts
- Reject extractions that violate domain/range constraints
- Flag low-confidence extractions for human review
- Track provenance: did this fact come from extraction, manual annotation, or inference?
