# Multilingual Extraction with LLMs

## The Multilingual Challenge

Enterprise knowledge graphs must handle data in multiple languages. A global company has customers in dozens of markets, each producing text in their local language. Traditional NLP pipelines required language-specific models—expensive and hard to maintain.

LLMs dramatically simplify multilingual extraction: "One LLM can extract entities and relations from dozens of languages without language-specific models." [existing prose]

## Cross-Lingual Transfer

Modern LLMs support cross-lingual transfer:

- **Train on high-resource languages** (English, Chinese, Spanish)
- **Apply to low-resource languages** (Swahili, Yoruba, Amharic)
- Zero-shot transfer works with 3-5 percentage point drop
- Fine-tuning closes the gap further

This works because LLMs learn universal linguistic structures during pretraining. Entity types (Person, Organization, Location) and relationship types (located_in, works_for, founded_by) are largely language-independent.

## Code-Switching Handling

Global systems encounter code-switching: mixing languages in the same text ("Ich want to buy das Produkt"). Traditional NLP pipelines break on code-switching. Modern LLMs handle it natively.

Key considerations:
- Detecting language boundaries
- Preserving entity references across languages
- Handling mixed-script text (Latin + Cyrillic + Chinese in same document)

## Multilingual Ontology Alignment

Different languages use different surface forms for the same concepts:

- English: "located in"
- German: "befindet sich in"
- Japanese: "に位置する"

The ontology must map these to a single relationship type. Options:

1. **Canonical relationship names** — English names, map translations at extraction
2. **Language-agnostic URIs** — Use ontology URIs (ex:locatedIn), not labels
3. **Multilingual labels** — Each ontology concept has labels in all supported languages

## Implementation Patterns

1. **Single model, many languages** — One LLM handles all extraction
2. **Language detection first** — Route to language-specific preprocessing if needed
3. **Translation layer** — Translate to English before extraction (last resort—loses nuance)
4. **Parallel extraction** — Extract from all language variants, merge

## Cost and Coverage

LLMs simplify multilingual extraction but don't eliminate cost:

- **Cost**: More tokens for multilingual prompts
- **Coverage**: Some languages have lower quality
- **Maintenance**: New languages require prompt updates, not model retraining

For most enterprises: "The LLM-based approach beats language-specific models on cost, maintenance, and coverage." [existing prose]
