# Multilingual Extraction with LLMs

## Argument
LLMs dramatically simplify multilingual extraction—one model handles dozens of languages without language-specific pipelines. This makes enterprise knowledge graphs feasible for global organizations.

## Why it matters (reliability goal)
Tie to Semantics pillar: meaning must be preserved across languages. The ontology must provide language-agnostic identity while supporting multilingual surface forms.

## Beats

1. **The Multilingual Challenge** — evidence: existing prose
   - Traditional NLP: language-specific models (expensive, hard to maintain)
   - LLMs: one model extracts from dozens of languages

2. **Cross-Lingual Transfer** — evidence: existing prose
   - Train on English, apply to low-resource languages
   - Zero-shot works with 3-5pp drop, fine-tuning closes gap

3. **Code-Switching Handling** — evidence: existing prose
   - Modern LLMs handle mixed-language text natively
   - Detecting language boundaries, preserving references

4. **Ontology Alignment** — evidence: ledger (RDF - language-agnostic URIs)
   - Different surface forms across languages
   - Use canonical URIs, not labels
   - Multilingual labels as fallback

5. **Implementation Patterns** — evidence: existing prose
   - Single model approach vs language detection routing
   - Translation layer as last resort
   - Parallel extraction and merge

6. **Cost and Coverage** — evidence: existing prose
   - LLM approach: lower cost, better coverage
   - Maintenance: prompt updates, not model retraining

## Conclusion to reach
The reader should understand that multilingual extraction is no longer a blocker—LLMs handle it natively, making global knowledge graphs feasible.
