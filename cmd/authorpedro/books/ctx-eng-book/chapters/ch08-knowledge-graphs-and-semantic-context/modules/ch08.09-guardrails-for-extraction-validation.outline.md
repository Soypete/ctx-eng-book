# Guardrails for Extraction Validation

## Argument
Extracted knowledge is not reliable knowledge. Guardrails validate extracted content against the ontology and against known facts—transforming the graph from "everything we extracted" to "everything we've validated."

## Why it matters (reliability goal)
Tie to Pragmatics pillar: the graph is a reliability layer, not just storage. Without validation, extracted content contains noise and errors that propagate to model outputs.

## Beats

1. **The Validation Problem** — evidence: existing prose draft
   - Extracted content contains noise, errors, contradictions
   - Need validation before storage

2. **Ontology-Based Validation** — evidence: ledger (Allemang & Sequeda 2024)
   - Domain rule: subject must belong to property's domain
   - Range rule: object must belong to property's range
   - OBQC catches 70% of domain violations

3. **Graph Consistency Validation** — evidence: existing prose draft
   - Temporal: does fact fit within valid time bounds?
   - Cardinality: does relationship violate constraints?
   - Negation: does explicit "not" contradict extraction?

4. **Confidence-Based Validation** — evidence: existing prose draft
   - Source confidence, model confidence, cross-reference confidence
   - High confidence → auto-accept; low confidence → human review

5. **Provenance Tracking** — evidence: ledger (KG Quality Dimensions - Zaveri et al.)
   - Source document, extraction method, timestamp, confidence, validation status

6. **Validation Pipeline** — evidence: existing prose draft
   - Extract → Ontology check → Consistency check → Confidence → Auto-accept/Review → Provenance

## Conclusion to reach
The reader should believe that guardrails transform the knowledge graph from "everything extracted" to "everything validated"—making it a true reliability layer.
