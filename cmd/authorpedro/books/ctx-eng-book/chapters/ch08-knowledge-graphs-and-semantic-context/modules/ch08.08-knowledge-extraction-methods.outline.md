# Knowledge Extraction Methods

## Argument
Different extraction methods suit different scenarios. NER finds predefined entity types, OpenIE discovers novel relationships, rules provide precision, and LLMs compress the entire pipeline. The pragmatic path is hybrid: LLM for extraction, rules for validation.

## Why it matters (reliability goal)
Tie to Pragmatics pillar: extraction method determines graph quality. Method selection is a cost-precision-recall tradeoff.

## Beats

1. **NER for Ontology Classes** — evidence: existing prose + ledger (Two versions of IE - knowledge graph book)
   - Identifies mentions of predefined concept classes
   - Output is typed entities ready for relationship extraction
   - Domain adaptation needed for specialized entities

2. **OpenIE for Discovery** — evidence: existing prose
   - Extracts relationships without predefined schema
   - No schema required, captures novel relationships
   - Tradeoff: high recall, low precision, no canonicalization

3. **Rule-Based for Precision** — evidence: existing prose
   - POS patterns, dependency parse, regex
   - High precision, interpretable, no training data
   - Low recall, high maintenance, domain-specific

4. **LLM-Based for Flexibility** — evidence: ledger (LLMs enabling novel entity extraction)
   - Compresses NLP pipeline: NER + coreference + RE in one prompt
   - Identifies novel entity types based on context
   - Cost tradeoff: low capex, high opex

5. **Hybrid Approach** — evidence: existing prose
   - LLM for extraction, rules for validation
   - Method selection depends on domain, data, precision requirements

## Conclusion to reach
The reader should understand that extraction method selection is a tradeoff—and that hybrid approaches (LLM + rules) provide the best balance of precision, recall, and maintainability.
