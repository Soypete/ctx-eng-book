# Instance Coverage and Ontology Population

## Argument
A knowledge graph's value depends not just on its schema, but on how much of the modeled domain is actually populated with data.

## Why it matters
An ontology without instances is a map without cities. Without measuring instance coverage, teams cannot distinguish between a well-designed but empty graph and one that actually serves AI systems.

## Beats

1. **The empty ontology problem** — evidence: kg-quality-metrics-notes (original research)
   - Many teams design beautiful ontologies, populate a few nodes, then discover the graph can't support inference
   - Example: a "Customer" class with zero instances, or only partial population (Customer exists, but Orders, Invoices missing)

2. **Instance coverage defined** — evidence: kg-quality-metrics-notes
   - Instance Coverage = Populated domain entities / Modeled domain entities
   - Design-time vs runtime: the metric changes as data is ingested

3. **What belongs in the graph vs what stays in source systems** — evidence: kg-quality-metrics-notes (graph as map, SCDs)
   - Slowly changing dimensions (organizations, people, taxonomies) → graph nodes
   - High-volume operational data (transactions, logs) → source systems
   - The graph links, doesn't duplicate

4. **Measuring population** — evidence: GAP (needs research)
   - Node count by class
   - Edge density by relationship type
   - Property fill rate per entity type
   - Comparison to expected population from data mesh

5. **The hydration problem** — evidence: kg-quality-metrics-notes (hydration coverage)
   - Even a populated graph can fail to retrieve context at runtime
   - Hydration coverage = successfully retrieved sources / known sources
   - This is a runtime instance coverage metric

## Conclusion to reach
A knowledge graph is only as useful as its populated instances. Context engineering requires measuring both design-time instance coverage (how much of the domain is modeled AND populated) and runtime hydration coverage (how much required context was actually retrieved).
