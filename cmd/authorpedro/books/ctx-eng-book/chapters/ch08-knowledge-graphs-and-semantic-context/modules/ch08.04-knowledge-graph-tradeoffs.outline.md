# Knowledge Graph Tradeoffs

## Argument
Knowledge graphs are not free—they require upfront modeling, ongoing maintenance, and operational overhead. The pragmatic path is domain-first: start with tools, learn the domain, then evolve to graphs.

## Why it matters (reliability goal)
Tie to Pragmatics pillar: cost-benefit analysis of graph adoption. Graphs provide reliability through explicit relationships, but at significant engineering cost.

## Beats

1. **Multiple Topical Graphs** — evidence: existing prose
   - Enterprise: HR, finance, infrastructure, customer, product graphs
   - Each with own ontology, governance, authorization, lifecycle
   - Bounded context and data mesh principles

2. **Domain-First Approach** — evidence: existing prose
   - Start with database: curated agent data with simple structure
   - Semantics emerge from tool relationships, not upfront modeling
   - Knowledge graph is end state, not starting point

3. **Why Dumb Tools Fail** — evidence: ledger (Allemang & Sequeda 2024)
   - Most "graph for AI" tools: structured storage, no reasoning
   - 70% of query errors stem from domain violations
   - OBQC (Ontology-based Query Check) catches errors

4. **The Reasoner Requirement** — evidence: ledger (Sequeda et al. 2024)
   - Domain rule: subject must belong to property's domain class
   - Range rule: object must belong to property's range class
   - Domain-range consistency: chained properties must align

5. **Structured Classification vs Wikis** — evidence: ledger (OKF - link graphs vs KG)
   - Wikis: domain-less search, fall apart at scale
   - Structured: explicit types, typed relationships, domain-specific schemas
   - Wing/Room/Drawer hierarchy outperforms wiki-based approaches

6. **Graph Algorithms as Runtime Tools** — evidence: existing prose
   - Dijkstra: cheapest/optimal path for context assembly
   - Tarjan: strongly connected components as retrieval units
   - Algorithm is runtime, ontology is design-time

7. **When Graphs Are the Right Tool** — evidence: existing prose
   - Start with: simple lookups, document retrieval, known relationships
   - Graduate to: discovery, variable-depth traversal, relationship attributes, authorization as traversal, multi-hop reasoning

8. **Costs** — evidence: ledger (Traditional vs LLM RE cost tradeoff)
   - Maintenance: ongoing curation, schema changes
   - Ingestion latency: slow for high-volume streaming
   - Live data mismatch: sync pipelines required

## Conclusion to reach
The reader should understand when knowledge graphs provide value (complex relationships, multi-hop reasoning) vs when they add unnecessary complexity (simple lookups, document retrieval).
