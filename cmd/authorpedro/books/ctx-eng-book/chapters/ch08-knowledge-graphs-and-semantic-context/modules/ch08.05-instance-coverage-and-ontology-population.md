# Instance Coverage and Ontology Population

## The Empty Ontology Problem

An ontology without instances is a map without cities. Many teams design beautiful ontologies, populate a few nodes, then discover the graph can't support inference.

My first knowledge graph was for education. We didn't have data for certain things. The database did not have a "classroom." There was no relationship in the database that related a group of teachers and students to the time they spent learning a subject. This could only be derived from enrollments.

Why was the classroom important? The class is where tests, assignments, grades all happened. Teachers assigned and graded. Students completed. Knowledge was assessed. Without the class, we could not appropriately traverse the graph to see what a student accomplished in a day and answer questions like: "What homework needs to be done?" "What tests are upcoming?" "What lecture was covered today?"

The classroom was in the picture, but the data was never hydrated. Ontologies are classification systems. But they are only powerful in a knowledge graph when they are used in a reasoner to make the relationships in a hydrated data store potent.

## Instance Coverage Defined

**Instance Coverage = Populated domain entities / Modeled domain entities**

This metric changes as data is ingested. At design-time, you model entities. At runtime, you populate them.

Example: You model Customer, Order, Invoice, Payment. But if you only populate Customer, your instance coverage is 25%. The graph looks complete in the schema but is empty in practice.

## What Belongs in the Graph vs What Stays in Source Systems

Slowly changing dimensions—organizations, people, taxonomies—belong as graph nodes. High-volume operational data—transactions, logs—belongs in source systems. The graph links; it doesn't duplicate.

The pattern: hydrate the relationships, not the facts. Use the graph to traverse across systems, not to replicate their data.

## Measuring Population

Track:
- Node count by class
- Edge density by relationship type
- Property fill rate per entity type
- Comparison to expected population from data mesh

## The Hydration Problem

Even a populated graph can fail to retrieve context at runtime. Hydration coverage = successfully retrieved sources / known sources. This is a runtime instance coverage metric—what we covered in Chapter 7.

A knowledge graph is only as useful as its populated instances.
