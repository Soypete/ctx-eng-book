# Entity Resolution and Relationship Traversal

## Argument
Knowledge graphs assume entities have identity, but in reality, the same entity exists across multiple systems with different identifiers. Entity resolution and relationship traversal are the operational challenges that determine whether a knowledge graph provides reliable context.

## Why it matters (reliability goal)
Tie to Pragmatics pillar: the agent must see consistent context regardless of which system it queries. Canonicalization ensures one view of the entity.

## Beats

1. **The Identity Problem** — evidence: existing prose
   - Same entity across systems with different IDs (Jane Doe = jane.d@ = user_789)
   - No universal identifier across systems
   - Identifiers change, similar names don't guarantee identity

2. **Resolution Strategies** — evidence: existing prose
   - Deterministic: exact match on email/phone/employee ID (high precision)
   - Fuzzy: similarity scoring (edit distance, phonetic, embedding)
   - Graph-based: relationship inference (if A and B both connect to C)

3. **Canonicalization** — evidence: ledger (Sequera et al. - KG improves accuracy)
   - Single authoritative representation per entity
   - Primary ID + alternate IDs + merge history + confidence score
   - Agent sees consistent context regardless of source system

4. **Relationship Traversal** — evidence: ledger (Graph as semantic router - kg-quality-metrics-notes)
   - Direct neighbors: one hop, works for simple cases
   - Multi-hop: A→B→C paths for complete context
   - Traversal explodes combinatorially—controlled strategies needed

5. **Controlled Traversal Strategies** — evidence: existing prose
   - Path finding: specific relationship types, not general traversal
   - Bounded depth: max 2 hops, explicit expansion beyond
   - Pattern matching: SPARQL/Cypher for expressivity
   - Ranking at each hop: relevance, freshness, permissions, cost

6. **Traversal as Context Assembly** — evidence: ledger (Context precision - kg-quality-metrics-notes)
   - Graph assembles relevant subgraph, not full dump
   - Different from vector search: "what documents are similar" vs "what facts are related"
   - Use both: vector for exploratory, graph for structured

## Conclusion to reach
The reader should believe that entity resolution and traversal are the operational challenges that make or break knowledge graph reliability—and that controlled strategies are essential.
