# Guardrails for Extraction Validation

## The Validation Problem

Extracted knowledge is not reliable knowledge. Without validation, extracted entities contain noise, relationships contain errors, and the knowledge graph becomes a liability rather than an asset.

Guardrails validate extracted content against the ontology and against known facts in the graph. The principle: "Context reduces hallucination. Guardrails validate it. The knowledge graph does both." [existing prose]

## Guardrail Types

### Ontology-Based Validation

Query the ontology before accepting extraction:

- **Domain rule** — Does the subject belong to the property's domain class?
- **Range rule** — Does the object belong to the property's range class?
- **Domain-range consistency** — Do chained properties align?

Research demonstrates this works: "70% of query errors stem from domain violations... OBQC catches these errors by validating queries against RDFS/OWL constraints." [Allemang & Sequeda, 2024]

### Graph Consistency Validation

Query the graph to ensure extracted facts don't contradict known facts:

- **Temporal consistency** — Does the extracted fact fit within valid time bounds?
- **Cardinality consistency** — Does adding this relationship violate cardinality constraints?
- **Negation** — Is there an explicit "not" fact that contradicts the extraction?

### Confidence-Based Validation

Not all extractions are equally certain. Track confidence scores:

- **Source confidence** — How reliable is the extraction source?
- **Model confidence** — What probability did the model assign?
- **Cross-reference confidence** — How many independent sources confirm the fact?

Low-confidence extractions go to human review. High-confidence extractions are auto-accepted.

### Provenance Tracking

Every extracted fact should track:

- **Source document** — Where did this come from?
- **Extraction method** — Which method produced it?
- **Timestamp** — When was it extracted?
- **Confidence** — How certain is the extraction?
- **Validation status** — Has this been reviewed?

## Validation Pipeline

1. **Extract** — LLM or rule-based extraction produces candidate triples
2. **Ontology check** — Validate against domain/range constraints
3. **Consistency check** — Query graph for contradictions
4. **Confidence score** — Assign confidence based on model output
5. **Auto-accept or review** — High confidence → auto-accept; low confidence → human review
6. **Provenance record** — Store source, method, timestamp

## Guardrails as Reliability Layer

The knowledge graph is not just storage—it's a reliability layer:

- Entities must be typed to be accepted
- Relationships must be defined to be valid
- Constraints must be satisfied to be stored
- Provenance must be tracked to be trusted

This transforms the knowledge graph from "everything we extracted" to "everything we've validated."
