# Tracing Context Assembly

## Argument
The context pipeline is a production system that needs the same observability as any other production system. Without traces, you cannot answer "why did the model do that?"

## Why it matters (reliability goal)
Tie to Pragmatics pillar: align model behavior with user intent. Without observability, you cannot measure whether context engineering is actually improving reliability.

## Beats

1. **The Reliability Question** — evidence: existing prose
   - Every production AI team must answer: why did the model do that?
   - Observability is not optional, it's the foundation

2. **The Context Pipeline Is a Production System** — evidence: existing prose
   - Pipeline should be instrumented like any production system
   - Context engineering builds the pipeline, observability makes it visible

3. **The Context Assembly Trace** — evidence: ledger (OpenTelemetry for AI Systems)
   - Combine prompt, retrieval, and tool lineage into a complete trace
   - Directed acyclic graph of spans, each representing a step
   - Answers the reliability question by showing exactly what the model saw

4. **OpenTelemetry for Context Systems** — evidence: ledger (OpenTelemetry Industry Adoption, OpenTelemetry for AI Systems)
   - OpenTelemetry is the standard framework for traces, spans, attributes [CNCF, 2026](https://cncf.io/projects/opentelemetry)
   - 27,863 contributors, 5,375 organizations, graduated from CNCF [CNCF, 2026](https://cncf.io/projects/opentelemetry)
   - Now the foundation for AI and cloud observability [CNCF, 2026](https://cncf.io/blog)

## Conclusion to reach
The reader should believe that context engineering requires observability as a prerequisite. Without the ability to trace context assembly, you cannot reliably improve your system.
