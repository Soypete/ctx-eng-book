# Prompt, Retrieval, and Tool Lineage

## Argument
Each component of the context pipeline—prompts, retrieval, tools—needs explicit lineage tracking. Without this tracking, failures are undebuggable.

## Why it matters (reliability goal)
Tie to Pragmatics pillar: understand how each input dimension affects model behavior. Lineage enables correlation between changes and outcomes.

## Beats

1. **Prompt Lineage** — evidence: existing prose
   - Track prompt version, system message content, few-shot examples
   - Critical for correlating prompt changes with quality degradation
   - Version prompt templates, record full content per request

2. **Retrieval Lineage** — evidence: existing prose + context precision research
   - Track what was fetched from which store, what query was used
   - Debug retrieval failures: wrong docs, wrong metadata, filtering issues
   - Context Precision = Useful Context / Retrieved Context [Research](research/_evidence-ledger.md)
   - Know which documents were included/excluded for cost optimization

3. **Tool Lineage** — evidence: existing prose
   - Track tools called, order, parameters, results
   - Debug unexpected tool calls and parameter extraction errors
   - Critical for multi-step tool use where chain of calls leads to output

## Conclusion to reach
The reader should believe that without explicit lineage tracking for each pipeline component, debugging production failures is nearly impossible.
