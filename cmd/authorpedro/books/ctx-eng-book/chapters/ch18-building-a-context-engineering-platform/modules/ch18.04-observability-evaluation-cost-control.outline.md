# Observability, Evaluation, and Cost Control

## Argument
Production systems must be measurable, observable, and testable at every layer. Evaluation runs at three levels—component, integration, behavioral—and the eval pipeline runs automatically on every change.

## Why it matters (reliability goal)
Tie to Pragmatics pillar: you can't improve what you don't measure. Evaluation at every layer is what makes the system reliable in production.

1. **Component Evaluations** — evidence: ledger (evaluation harness is a system for measuring quality [arXiv:2311.04220](https://arxiv.org/abs/2311.04220); retrieval quality: precision, recall, reduction ratio, pair completeness, provenance [arXiv:2307.03109](https://arxiv.org/abs/2307.03109))

2. **Integration Evaluations** — evidence: existing prose

3. **Behavioral Evaluations** — evidence: existing prose

   - Score correctness, safety, usefulness
   - Track drift over time

4. **Evaluation Pipeline Automation** — evidence: existing prose
   - Component tests on every code change
   - Integration tests on every model change
   - Behavioral evals on every deployment
   - Dashboards and alerts for degradation

## Conclusion to reach
The reader should understand that a production-ready system is one where every layer is testable, every boundary is enforceable, and every failure is observable.
