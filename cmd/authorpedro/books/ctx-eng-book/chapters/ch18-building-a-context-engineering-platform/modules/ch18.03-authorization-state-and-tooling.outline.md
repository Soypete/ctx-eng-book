# Authorization, State, and Tooling

## Argument
Permissions are not an afterthought—they're embedded in every layer of the platform. Defense in depth: no single layer is perfect, but layers compose to make violations impossible. Memory is a system of temporal layers, each serving a different retrieval horizon.

## Why it matters (reliability goal)
Tie to Pragmatics pillar: without permissions at every layer, the system leaks data. Without memory, the system starts fresh every request—accumulating knowledge is what production looks like.

## Beats

1. **Permissions at Every Layer** — evidence: ledger (Traditional RBAC models fail to capture dynamic, multi-step agent actions; capability-based access provides fine-grained, revocable permissions tied to specific actions [Brandstetter et al., 2024](https://arxiv.org/abs/2412.10891))
   - Store level: PostgreSQL RLS enforced by database
   - Retrieval level: capability-based filtering (capability sets: what stores, fields, time ranges)
   - Assembly level: permission boundary injected into prompt
   - Output level: validate tool calls against capability set

2. **Authorization Failure Modes** — evidence: ledger (RAG systems introduce attack surfaces where malicious documents can be retrieved and injected, leading to data leakage, prompt manipulation [Shift, 2024](https://www.shift.com/blogs/the-hidden-dangers-of-retrieval-augmented-generation); agent refusal varies from 100% down to 38% across models in authorization scenarios [Kodathala, 2026](https://arxiv.org/abs/2607.05518))
   - Dangerous retrieval: malicious documents injected into context
   - Context-to-execution integrity: agents read attacker-writable context
   - Tool execution needs separate authority check

3. **Memory Systems** — evidence: ledger (episodic memory records what happened, semantic memory records what system believes true, procedural memory records how system should act [episodic-periodic-memory.md]; false recollection, summary corruption, stale semantic memory, bad procedural generalization, memory poisoning, unauthorized recall are failure modes [arXiv:2304.03442](https://arxiv.org/abs/2304.03442))
   - Session memory: current conversation (fast cache, Redis)
   - User memory: persistent user state with RLS (preferences, history)
   - System memory: shared organizational knowledge with access controls

4. **Memory as Temporal Layers** — evidence: existing prose
   - Retrieval queries session → user → system
   - Results merge into context assembly
   - Memory enables accumulation vs. starting fresh

## Conclusion to reach
The reader should believe that permissions must be architectural (not trust-based) and that memory systems have distinct failure modes requiring governance.
