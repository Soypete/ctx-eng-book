# Source and Ingestion Architecture

## Argument
A context engineering platform is not a single system but a composition of specialized stores, retrieval pipelines, authorization layers, and evaluation infrastructure. The key architectural insight is that these layers are independent—interfaces between layers are the architecture.

## Why it matters (reliability goal)
Tie to Pragmatics pillar: production systems require testable boundaries, enforceable permissions, and measurable quality. Without this architecture, you can't debug failures, enforce security, or reason about system behavior.

## Beats

1. **End-to-End Architecture** — evidence: existing prose + ledger (Google's Conversational Analytics combines Knowledge Catalog, context bundles, graph, embeddings, citations, and query auditing—format provides knowledge, platform provides trust [Google, 2024](https://cloud.google.com/bigquery/docs/omnichannel-analytics-introduction))
   - Five layers: Ingestion → Storage → Retrieval → Assembly → Evaluation
   - Each stage is a function with clear inputs and outputs
   - Swappable components through well-defined interfaces

2. **Knowledge Stores** — evidence: ledger (graph should be semantic layer over distributed data mesh—stores ontology, relationships, identifiers, provenance, authorization boundaries, source mappings; operational data remains in PostgreSQL, Iceberg, Delta Lake, APIs [arXiv:2307.03367](https://arxiv.org/abs/2307.03367))
   - Document store: wiki, KB, reference materials (PostgreSQL FTS, Elasticsearch, vector DB)
   - Graph store: entities, relationships, ontology (Neo4j, Neptune)
   - Relational store: user profiles, transactions, state (PostgreSQL RLS)
   - Event store: conversation history, tool executions (for memory systems)
   - Multiple specialized stores > monolithic knowledge base

3. **Ingestion Pipeline** — evidence: existing prose
   - Data enters through normalized interfaces
   - Transformations applied consistently
   - Metadata captured for provenance

## Conclusion to reach
The reader should understand that production context engineering requires a composed architecture with specialized stores, clear interfaces between layers, and the recognition that the platform provides trust around the knowledge format.
