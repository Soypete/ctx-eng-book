# Tokens, Embeddings, and Attention

## Argument
Tokens, embeddings, and attention form the foundation of what models see. Understanding these mechanisms is prerequisite to engineering reliable context—because if you don't know what a token is, you can't reason about what the model sees.

## Why it matters (reliability goal)
Tie to Semantics pillar: the model operates on tokenized, embedded representations. What enters attention determines what can influence output. No visibility into this layer = no reliability engineering.

## Beats

1. **Tokens Are Not Words** — evidence: existing prose
   - Subword tokenization varies across models
   - Same text = different token counts across GPT-4, Claude, open-source
   - Implications: context limits, pricing, retrieval boundaries

2. **Embeddings Are Fixed-Dimensional Statistical Patterns** — evidence: existing prose
   - Embeddings are learned statistical representations, not semantic understanding
   - Similar meanings cluster but the model doesn't "understand" relationships
   - Retrieval failure mode: statistically similar ≠ semantically relevant

3. **Attention Is a Competition for Bounded Resource** — evidence: research/attention-is-all-you-need-notes.md (Vaswani et al., 2017), ledger (attention competition)
   - Every token in context competes for attention
   - No pre-filtering: system prompt vs user message vs retrieved docs all compete equally
   - Order and composition determine attention distribution

4. **The Core Distinction: Attention vs Context Engineering** — evidence: research/attention-is-all-you-need-notes.md
   - Attention selects what information is *important* from what's *available*
   - Context engineering selects what information is *available* in the first place
   - These are complementary layers

## Conclusion to reach
The reader should understand that the model doesn't "see" text—it sees tokenized vectors competing for attention. Without understanding this layer, you cannot debug failures, optimize costs, or reason about behavior.
