# The Future of AI Engineering

## Argument
Context engineering breaks into distinct specializations—data, retrieval, state, authorization, platform, evaluation—and the future is teams of specialists around a shared context platform.

## Why it matters (reliability goal)
Tie to Pragmatics pillar: no single person can do all context engineering well. Specialization enables reliability.

## Beats

1. **Data Engineering for AI** — evidence: ledger (Data Is Not a Shortcut for Cost)
   - Building pipelines that transform raw data into retrievable context
   - [webinformationextraction](research/knowledge-graphs/webinformationextraction.md) — "Data is expensive. LLMs are NOT a shortcut"

2. **Retrieval Engineering** — evidence: ledger (Hybrid Retrieval, Context Assembly Pipelines)
   - [context-assembly-pipeline-patterns](research/context-assembly-pipeline-patterns.md) — context assembly is the query pipeline
   - Beyond vector search: hybrid retrieval, query understanding, reranking

3. **State Engineering** — evidence: ledger (Agent Memory as Database Workload)
   - [Orogat & Mansour, 2026](https://arxiv.org/2605.26252) — GEM: Governed Evolving Memory

4. **Authorization Engineering** — evidence: ledger (Capability-Based Access for AI Agents)
   - [Brandstetter et al., 2024](https://arxiv.org/2412.10891) — capability-based access for dynamic agent actions

5. **Platform Engineering** — evidence: ledger (OpenTelemetry Industry Adoption)
   - [CNCF OpenTelemetry](https://cncf.io/projects/opentelemetry) — 27,863 contributors, industry standard

6. **Evaluation Engineering** — evidence: ledger (Agent Evals Need Harnesses)
   - [llms-in-production/chapter-7](research/llms-in-production/chapter-7.md) — a harness is a system for evaluation

## Conclusion to reach
The reader should believe that context engineering is the essential specialization for production AI, following the same trajectory as data engineering.
