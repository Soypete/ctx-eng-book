# Freshness, Consistency, and Partial Failure

## Argument
Context assembled from queries has a temporal dimension. Every query result is a snapshot at a specific time. Different sources at different times can conflict. Context pipelines must handle temporal inconsistency and partial failure.

## Why it matters (reliability goal)
Without freshness metadata, consistency guarantees, and failure handling, the pipeline assembles unreliable context. The model receives contradictory facts or incomplete information without knowing.

## Beats

1. **Temporal Consistency in Context Pipelines** — evidence: existing prose
   - Vector store indexed at t₁, database query at t₂, API at t₃
   - Freshness requirements: user profile (hours old), order status (minutes), real-time pricing (seconds)
   - Implement freshness metadata: timestamp every query result, enforce thresholds

2. **Eventual vs Strong Consistency** — evidence: existing prose
   - Strong: wait for all sources to sync → slow
   - Eventual: return immediately with available data → fast but risk of contradictions
   - Pattern: query all sources in parallel, tag with timestamps, fail on critical timeouts

3. **Partial Failure Modes** — evidence: GAP (needs research)
   - Five queries: two succeed, two timeout, one error
   - Naive: fail whole request if any query fails → fragile
   - Robust: partial context acceptable with clear failure signaling

4. **Retry Strategies** — evidence: existing prose
   - Exponential backoff with jitter
   - First attempt: parallel. On timeout: async refetch. On error: retry once then fail.
   - Never block pipeline waiting for slow source

5. **Handling Inconsistent State** — evidence: existing prose
   - Contradictions happen: user "Basic" in profile, "Premium" in billing
   - Don't hide contradictions—present both with source attribution
   - Model can reason about conflicts

## Conclusion to reach
Context from queries is temporal, potentially inconsistent, and subject to partial failure. Handle through freshness metadata, eventual consistency, partial failure handling, retry limits, and source attribution.
