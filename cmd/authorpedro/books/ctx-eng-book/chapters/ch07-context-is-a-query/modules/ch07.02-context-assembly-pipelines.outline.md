# Context Assembly Pipelines

## Argument
Every production AI system runs multiple query types simultaneously. Context assembly pipelines concatenate query results into a single prompt. The reliability of the AI system is the reliability of this pipeline.

## Why it matters (reliability goal)
Context engineering IS query engineering. Each query is a failure point. Each result is a potential source of noise. Each concatenation is a potential context pollution event.

## Beats

1. **The Context Assembly Pipeline** — evidence: existing prose + ledger (context-assembly-pipeline-patterns)
   - Single request involves multiple query types: SQL, API, vector search, stream, lakehouse
   - Pipeline must: execute in parallel, handle partial failures, truncate results, order logically, log observability
   - [Context assembly patterns](research/context-assembly-pipeline-patterns.md): query pipeline that assembles context from multiple sources before inference

2. **Reliability Through Query Engineering** — evidence: existing prose
   - Shift focus: "how do we store context" → "what queries produce context?"
   - Model sees only query results. Quality of results = quality of output.
   - Build better queries, get better context. Build unreliable queries, get unreliable AI.

## Conclusion to reach
Context is not stored. Context is assembled from query results. Engineering context means engineering queries.
