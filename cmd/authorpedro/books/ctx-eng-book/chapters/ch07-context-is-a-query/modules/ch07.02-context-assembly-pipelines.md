# Context Assembly Pipelines

## The Context Assembly Pipeline

Every production AI system runs multiple query types simultaneously. A single request might involve:

1. A SQL query for user profile data from PostgreSQL
2. An API call for external service status
3. A vector search for relevant documents
4. A stream query for recent events
5. A lakehouse query for aggregated metrics

Each query returns results. The context assembly pipeline concatenates these results into a single prompt:

```
System: You are a customer support agent.

User profile (from SQL):
- Name: Jane Doe
- Tier: Premium
- Account since: 2023-01-15

Recent orders (from SQL):
- Order #1234: Delivered
- Order #1235: In transit

Relevant documents (from vector search):
- FAQ: Refund policy...
- Previous ticket: Jane requested...

Recent events (from Kafka):
- 10:00: Order #1235 shipped
- 10:15: User viewed tracking page

Aggregated behavior (from Snowflake):
- Average order value: $127
- Preferred category: electronics

User: Where is my order?
```

This is the context the model sees. Every line is a query result. No stored context. No pre-loaded memory. Only assembled query results.

The assembly pipeline must:

- Execute queries in parallel where possible
- Handle partial failures (some queries succeed, others fail)
- Truncate or summarize results that exceed token limits
- Order results logically (user profile before questions about the user)
- Log which queries ran and what they returned (observability)

The reliability of the AI system is the reliability of this pipeline. Each query is a failure point. Each result is a potential source of noise. Each concatenation is a potential context pollution event.

## Reliability Through Query Engineering

The reliability question for any AI system is: which systems contribute information, and how?

Every contributing system is a query. Every query can fail, return wrong results, or return incomplete results. Context engineering is query engineering.

This shifts the engineering focus:

- Instead of "how do we store context," ask "what queries produce context?"
- Instead of "how do we retrieve memory," ask "what does each query return?"
- Instead of "why did the model fail," ask "what did each query actually return?"

The model sees only query results. The quality of those results determines the quality of the model's output. Build better queries, get better context. Build unreliable queries, get unreliable AI.

Context is not stored. Context is assembled from query results. Engineering context means engineering queries.

The systems that produce reliable AI are not the ones with the largest context windows. They're the ones with the best query pipelines.
