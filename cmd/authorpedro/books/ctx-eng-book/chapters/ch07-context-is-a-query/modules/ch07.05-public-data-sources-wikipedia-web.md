# Public Data Sources: Wikipedia and Web Indexing

## The Public Data Gap

Most RAG systems focus on private, proprietary data. Public data—Wikipedia, web indexes—is often ignored. Yet these sources are already curated, linked, and often source-cited.

My first RAG system was a DuckDuckGo web search tool in the PedroGPT Twitch bot. This was before tool calling existed—I used regex text matching to detect when to trigger a search. It was bad at inferring when to run the tool but good at executing when explicitly told to "search for latest golang release." This was retrieval-augmented generation, but not vendor search.

I first used vector similarity for address matching. Addresses have weird name inconsistencies—one might be "Lane," "Ln," or "LANE." Vector distance catches these. [Add cosine similarity diagram: the similarity is the shadow—vectors projecting onto each other, close vectors cast similar shadows.]

Early RAG was just: are vectors close? LLMs make it sound pretty. Then came Graph RAG—the idea that vectors don't include semantic relationships, so we need a graph to model those. But then we used LLMs to generate the graphs, and that introduced a new problem: no determinism.

Now I tend to use web search to validate information. I actually really like adding WikiSearch to agents—pulling from Wikipedia, then looking up references if I need a follow-up. This is a much better way to get the guardrails that RAG provides when trying to validate information.

## Wikipedia as Structured Context

Wikipedia articles contain structured elements: infoboxes, sections, citations. Links between articles create a graph structure—essentially HATEOAS (Hypermedia as the Engine of Application State). LLMs are already trained on web pages. They understand link navigation.

This is a pattern LLMs will see a lot. It leverages existing training.

Example: "give me all cities in France" → traverse the France article → parse the infobox → follow category links.

## Google/Web Indexing as Aggregator

Google's web index aggregates public data from across the web. Custom search engines can target specific domains. `site:wikipedia.org "topic"` gives source-backed queries.

The practical pattern: combine internal context (private) with public context (Wikipedia, web). The public layer provides background knowledge that private data assumes.

## Attribution and Citation Tracking

Wikipedia includes citations—you can trace back to primary sources. Google results show source domains. This matters for reliability: you know where public context came from.

- Wikipedia API: [MediaWiki Wikibase Data Model](https://www.mediawiki.org/wiki/Wikibase/DataModel) — includes precision for temporal values (seconds to billion years)
- Google Custom Search: [Google Search Documentation](https://developers.google.com/custom-search)
