# Personalization Failures as Missing Context

Personalization in AI systems means tailoring responses to a specific user—their preferences, history, permissions, and constraints. When this context is missing, wrong, stale, or over-scoped, the system fails in ways that feel personal but are actually context failures.

## Missing User Preferences

A user asks the AI for recommendations and gets generic responses instead of personalized ones. The model doesn't know what the user prefers because that context was never assembled.

The gap: no user preference context was provided. Learning crawlers can learn user preferences from a topic—they observe what the user engages with and build a model of preferences within that domain [wordnet-anchor-text-notes]. Without this, every user gets the same baseline response.

## Wrong User Context (Data Leakage)

A user sees another user's data. This is the most serious personalization failure—a privacy breach that feels like a model bug but is actually a context scoping failure.

RAG systems introduce new attack surfaces where malicious documents can be retrieved and injected into the model's context, leading to data leakage [Shift, 2024]. When personalization context isn't bound to the correct user identity, the model can inadvertently surface another user's information.

The fix: user identity must be bound to context scope at retrieval time, not assumed from the session.

## Stale Personalization

A user updates their preferences, but the AI still behaves as if nothing changed. Last month's preferences are still being used.

False recollection, summary corruption, stale semantic memory, bad procedural generalization, memory poisoning, unauthorized recall—these are the failure modes that distinguish reliable memory from naive storage [Park et al., 2024]. Personalization context needs freshness metadata just like any other context.

The fix: timestamp user preferences, set staleness thresholds per preference type, trigger refresh when thresholds are exceeded.

## Over-Scoped Personalization

The model accesses more user data than needed for the task. Personalization becomes an attack vector—providing more context than necessary increases the blast radius of any compromise.

The fix: personalization context should be scoped to the minimum required for the current task, with capability-based access enforcement [Brandstetter et al., 2024].

## Summary

Personalization failures are context failures:

- Missing preferences → generic output
- Wrong user context → data leakage
- Stale preferences → wrong output
- Over-scoped context → increased attack surface

The pattern is consistent: treat personalization as context assembly, not as model memory.
