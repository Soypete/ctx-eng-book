# User, Session, and Workflow State

## Argument
Production AI systems handle three distinct types of state—user, session, and long-term—each with different storage requirements, access patterns, and consistency needs.

## Why it matters (reliability goal)
Tie to Pragmatics pillar: understanding state types determines architecture decisions.

## Beats

1. **Three Types of State** — evidence: existing prose + ledger (open-knowledge-format-notes: knowledge lifecycle is stateful)
   - User state: persistent, identity-associated, long-term storage
   - Session state: ephemeral, conversation-associated, fast-access storage
   - Long-term state: between user and session, agent workspace

2. **State Storage Patterns** — evidence: existing prose
   - User → databases, document stores, knowledge graphs
   - Session → Redis, in-memory caches
   - Long-term → vector databases, specialized memory systems

3. **The Reliability Question Answered** — evidence: existing prose + ledger (Orogat & Mansour 2026)
   - State lives in systems you build
   - No other option—model has no state
   - See: [Orogat & Mansour, 2026](https://arxiv.org/abs/2605.26252) — GEM state-level operators

## Conclusion to reach
The reader should be able to identify where state lives in any AI system they build.
