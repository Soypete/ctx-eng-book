# ch06.03 User, Session, and Workflow State

## Three Types of State

Production AI systems handle three distinct types of state, each with different storage requirements, access patterns, and consistency needs.

**User state** is persistent data associated with an identity—preferences, permissions, history, accumulated knowledge. This lives in long-term storage: databases, document stores, knowledge graphs. It changes slowly, is shared across sessions, and must be governed by authorization rules.

**Session state** is ephemeral data associated with a single conversation or interaction chain. This includes the current conversation history, in-progress work, and temporary variables. Session state lives in fast-access storage: in-memory caches, Redis, or lightweight databases. It changes rapidly within a session and is discarded when the session ends.

**Long-term state** sits between user state and session state—accumulated agent workspace, learned patterns, derived knowledge. This is what agent memory systems actually manage. It's persistent like user state but operationally relevant like session state.

The reliability question—where does state actually live?—has a precise answer: in the systems you build to store it. There is no other option. The model has no state. Every "memory" is stored externally and retrieved on demand.
