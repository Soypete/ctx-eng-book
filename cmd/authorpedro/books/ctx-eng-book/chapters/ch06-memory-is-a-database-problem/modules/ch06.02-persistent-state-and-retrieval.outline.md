# Persistent State and Retrieval

## Argument
The data platform beneath AI systems is the real architecture. Memory systems are database engineering with retrieval semantics.

## Why it matters (reliability goal)
Tie to Pragmatics pillar: storage, indexing, retrieval, and governance map to existing database technology.

## Beats

1. **State Mapping to Storage Systems** — evidence: existing prose + ledger (open-knowledge-format-notes: "Knowledge lifecycle is stateful, not a prompt pattern")
   - User state → relational/documents/knowledge graphs
   - Session state → Redis/Memcached (fast, ephemeral)
   - Long-term state → vector databases, memory systems

2. **The Data Platform Beneath AI** — evidence: existing prose
   - Retrieval pipeline = query engine
   - State store = database
   - Context assembly = ETL pipeline

3. **Reliability Through Engineering** — evidence: existing prose + ledger (episodic-periodic-memory.md reliability failure modes)
   - Storage reliability → state persists
   - Index reliability → state is findable
   - Retrieval reliability → right state returned
   - Authorization reliability → state access governed

4. **Long-term state in practice** — evidence: existing prose
   - Mem0: hierarchical distillation
   - Letta: Context Repositories
   - LangMem: explicit tool calls

## Conclusion to reach
The reader should understand that the agents that "remember" best have the best data platforms beneath them. Memory is infrastructure, not a feature.
