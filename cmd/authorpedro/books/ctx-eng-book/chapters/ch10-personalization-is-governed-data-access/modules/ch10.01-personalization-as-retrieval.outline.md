# Personalization as Retrieval

## Argument
Authorization is a data platform problem, not a prompt problem. Models are not access control systems—they are pattern matchers. Authorization belongs at the storage layer, enforced consistently, logged reliably, and audited precisely.

## Why it matters (reliability goal)
**Pillar:** Governance
**Reliability Goal:** Ensure models only access data they're authorized to see
**Failure Mode:** Data leaks through prompt injection, hallucinated permissions, or retrieval bugs

## Beats

1. **Authorization Is Not a Prompt Problem** — evidence: ledger (Rashidi 2026, Kodathala 2026)
   - Prompt-based authorization is non-deterministic, unauditable, and unreliable
   - Authorization failures happen at the data layer, not in the prompt
   - The data platform must enforce authorization, not the model

2. **ABAC for Agents** — evidence: ledger (Brandstetter et al., 2024)
   - Attribute-Based Access Control: subject, resource, and action attributes
   - Maps directly to AI systems: agent (subject), context (resource), retrieval (action)
   - More flexible than RBAC—attributes can be combined and evaluated dynamically

3. **The Authorization Question** — evidence: existing prose
   - Every production AI system must answer: who is allowed to see what?
   - This is a core context engineering challenge
   - Different stores have different permission models—context engineering must bridge them

## Conclusion to reach
Authorization belongs in the data platform, not in the prompt. The prompt can express intent. The data platform must enforce it.
