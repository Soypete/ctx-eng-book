# Planning and ReAct

## Argument
Most agents are workflows wearing a trench coat. The model provides intelligence; the workflow provides reliability. ReAct and planning patterns externalize reasoning into software-controllable structures.

## Why it matters (reliability goal)
Tie to Pragmatics pillar: when the model decides vs. software decides. The agent is only as reliable as the workflow that runs it.

## Beats

1. **ReAct Pattern** — evidence: existing prose + ledger (Teleprompters vs MCP/ReAct)
   - Interleaves thought, action, observation in a loop
   - Forces model to externalize reasoning in parseable format
   - Enables software to intervene: reject dangerous tools, terminate infinite loops

2. **Planning Patterns** — evidence: existing prose
   - Tree search: generate N candidates, simulate outcomes, pick best
   - MCTS: statistical sampling for large search spaces
   - Plan refinement: rough plan, refine as you go

3. **State of the Stack** — evidence: existing prose
   - Standards: ReAct Protocol, Agent Protocol
   - Infrastructure: LangGraph, LangChain, AutoGen, Temporal
   - Questions to ask before adoption

## Conclusion to reach
The reader should believe that ReAct and planning patterns move complexity from the model's context window to software infrastructure. Reliability comes from software maintaining plan state, not from the model holding it in context.
