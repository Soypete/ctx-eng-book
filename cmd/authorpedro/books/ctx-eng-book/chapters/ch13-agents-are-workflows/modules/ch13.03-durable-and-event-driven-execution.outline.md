# Durable and Event-Driven Execution

## Argument
Agents run for minutes or hours. Infrastructure fails in seconds. Durable execution ensures agent progress survives system failures. Many production agents are event-driven systems, not loops.

## Why it matters (reliability goal)
Tie to Pragmatics pillar: production agents require checkpointing and event-driven architectures. Without durable execution, a 30-minute task fails permanently on a 5-minute infrastructure failure.

## Beats

1. **Durable Execution** — evidence: ledger (Orogat & Mansour 2026; Zhang et al. 2026)
   - Checkpointing: saving complete agent state at safe points
   - Includes: state machine state, accumulated context, pending tool calls, execution metadata
   - Approaches: database persistence, event sourcing, message queues, saga patterns
   - Ledger: "Long-term agent memory is a new data-management workload... GEM replaces record-level database operations with four state-level operators"

2. **Event-Driven Agent Systems** — evidence: existing prose
   - Pattern: event arrives → agent initializes → executes → produces output
   - Changes reliability engineering: stateless initialization, idempotency, timeout handling, event ordering

## Conclusion to reach
The reader should believe that durable execution is not optional for production agents. Event-driven architectures require different reliability engineering than loop-based agents.
