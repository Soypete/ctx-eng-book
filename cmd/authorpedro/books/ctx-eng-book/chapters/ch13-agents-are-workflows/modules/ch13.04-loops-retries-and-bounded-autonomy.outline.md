# Loops, Retries, and Bounded Autonomy

## Argument
The reliability question answered: when should the model decide, when should software decide? Loops are where agents become unreliable. Bounded autonomy gives the model freedom within software-controlled boundaries.

## Why it matters (reliability goal)
Tie to Pragmatics pillar: if a decision can be expressed as rules, codify in software. If the decision requires judgment beyond rule expression, let the model decide—with software guarding boundaries.

## Beats

1. **The Decision Boundary** — evidence: existing prose
   - Software decides for: structural, infrastructure, safety, governance concerns
   - Model decides for: reasoning, context, output, adaptation concerns
   - Heuristic: if it can be expressed as rules, codify it

2. **Loops and Retries** — evidence: existing prose
   - Loop patterns: fixed iteration, convergent exit, checkpointer loop
   - Retry strategies: exponential backoff, fixed retry, circuit breaker
   - Exit conditions: max iterations, quality threshold, staleness, resource exhaustion

3. **Bounded Autonomy** — evidence: existing prose
   - Model decides how to reason; workflow decides how to reason safely
   - Software controls: attempts, runtime, resources, allowed actions

## Conclusion to reach
The reader should believe that the boundary between model and software decisions isn't fixed—it depends on reliability requirements, task predictability, and safety constraints. The principle is bounded autonomy: autonomy within boundaries, software enforces the boundaries.
