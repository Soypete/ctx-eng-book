# Retrieval and Execution Boundaries

## Argument
Dangerous retrieval is the primary failure mode for AI systems. Capability-based access makes it structurally impossible to retrieve unauthorized data.

## Why it matters (reliability goal)
Answer the chapter's reliability question: "How do we prevent dangerous retrieval?"—through structural enforcement, not prompt instructions.

## Beats

1. **The Reliability Argument** — evidence: existing prose + ledger (Santos-Grueiro, Kodathala)
   - Dangerous retrieval: wrong data, too much, too little, wrong kind
   - Cause: permission-related failures

2. **Structural Enforcement** — evidence: existing prose
   - Agent can't retrieve outside capability
   - Data store enforces capability
   - Permission is structural, not advisory

3. **The Answer** — evidence: existing prose
   - Every retrieval carries a capability
   - Capability generated from user authorization + task requirements
   - Provenance records authorization

## Conclusion to reach
The reader should believe that dangerous retrieval is prevented not by trusting the model, but by structural enforcement at the data store layer.
