# RBAC, ABAC, and Capability-Based Access

## Argument
Traditional RBAC is too coarse for agents. Capabilities provide granular, scoped, revocable permissions matched to specific operations.

## Why it matters (reliability goal)
Role-based systems are binary (allowed/not). Capability-based systems are granular—exactly this data, operation, duration.

## Beats

1. **RBAC and Its Limits** — evidence: existing prose
   - Roles reflect job function, not specific tasks
   - Map roles to task-specific capabilities

2. **OAuth for Delegated Access** — evidence: existing prose
   - Standard protocol for delegated authorization
   - Token scopes define what agent can access
   - Time-limited, revocable tokens

3. **OpenID Connect for Agent Identity** — evidence: existing prose
   - Identity layer on top of OAuth
   - ID token: who agent is acting as
   - Access token: what agent can do

4. **Capability-Based Access** — evidence: ledger (Brandstetter et al., 2024)
   - Specifies: resource, action, constraints, grantor
   - Self-enforcing at data store

## Conclusion to reach
The reader should understand OAuth and OpenID Connect as the foundation for agent authorization, with capabilities providing the granularity agents need.
