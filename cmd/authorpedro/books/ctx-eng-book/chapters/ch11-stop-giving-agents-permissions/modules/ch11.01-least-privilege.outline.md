# Least Privilege

## Argument
Give agents exactly the permissions needed for the current task—no more. Broad permissions cause context contamination, dangerous retrieval, and cascade failures.

## Why it matters (reliability goal)
Tie to Pragmatics pillar: alignment requires correct, complete context. Broad permissions guarantee noise in context, increasing unreliability.

## Beats

1. **The Permission Problem** — evidence: existing prose
   - Agents given too much access → unreliable systems
   - Assumptions: agents need broad access to be useful (wrong)

2. **Why Broad Permissions Fail** — evidence: existing prose
   - Context contamination: retrieves irrelevant data, lowers signal-to-noise
   - Dangerous retrieval: retrieves sensitive data accidentally
   - Cascade failures: single point of compromise exposes everything

3. **Least Privilege for Agents** — evidence: ledger (capability-based access)
   - Task-scoped capabilities: granted per operation, expire after
   - Capability-based authorization: verify capability, not role
   - Authorization is enforcement at retrieval layer, not prompt

## Conclusion to reach
The reader should believe that broad permissions are the root cause of unreliable AI systems. The fix is capability-based access—scoped, temporary, and enforced at the data store.
