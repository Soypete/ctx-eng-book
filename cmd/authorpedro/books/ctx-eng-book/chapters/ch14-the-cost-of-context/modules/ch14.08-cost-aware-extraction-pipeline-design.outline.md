# Cost-Aware Extraction Pipeline Design

## Argument
Full extraction pipelines have costs at every stage—ingestion, processing, storage, retrieval. Cost-aware design means understanding and optimizing each stage while maintaining the required reliability.

## Why it matters (reliability goal)
Tie to Pragmatics pillar: the cheapest reliable solution requires measuring and optimizing the full pipeline, not just the extraction step.

## Beats

1. **Pipeline Cost Components** — evidence: existing prose
   - Ingestion: parsing, chunking, embedding generation
   - Processing: NER/RE inference or LLM calls
   - Storage: vector DB, knowledge graph
   - Retrieval: query embedding, search, graph traversal

2. **Optimization Strategies** — evidence: existing prose
   - Size chunks to consumption (not maximums)
   - Cache extracted entities (done once, queried many)
   - Route by complexity (rules for simple, LLMs for complex)
   - Parallelize extraction (embarrassingly parallel)
   - Monitor efficiency frontier

3. **The Reliability Question** — evidence: ch14.05-context-efficiency-metrics
   - What extraction accuracy does downstream actually require?
   - Can you tolerate "good enough" with guardrails?
   - Cost of false positives vs false negatives in your domain

4. **Scaffolding Tax** — evidence: scaffolding-tax-ai-utah-talk.md
   - Extracting with LLMs adds to the scaffolding tax
   - Every extraction step is compute that could be data platform work

## Conclusion to reach
The reader should believe that extraction pipeline design must be cost-aware end-to-end. The cheapest reliable solution is an engineering choice across all pipeline stages.
