# Context Efficiency Beyond Token Cost

## Argument
Context efficiency must be measured across multiple dimensions—tokens, latency, cost, API calls, storage lookups—not just token count.

## Why it matters
Two systems can produce equivalent outputs but differ dramatically in efficiency. Without measuring retrieval latency, API calls, and storage lookups, teams optimize for token cost while ignoring equally important runtime performance.

## Beats

1. **Token economics is not enough** — evidence: ch14.01-token-and-context-economics
   - Token cost is important but incomplete
   - System A: 1000 tokens, 10 API calls, 500ms latency
   - System B: 1500 tokens, 2 API calls, 100ms latency
   - Which is more efficient? Depends on the trade-off weights

2. **Context efficiency defined** — evidence: kg-quality-metrics-notes
   - Context Efficiency = Reliable output / Total resource consumption
   - Resources: tokens, retrieval latency, retrieval cost, hydration time, API calls, storage lookups
   - Multi-dimensional metric, not single-number

3. **Measuring retrieval latency** — evidence: ch14.02-retrieval-tool-and-latency-costs
   - Time to first context token
   - Time to full context assembly
   - Per-source latency breakdown
   - Degradation alerting

4. **Measuring API and storage costs** — evidence: GAP
   - API calls per context assembly
   - Storage lookups per request
   - Cache hit/miss ratios
   - Network hops between services

5. **The efficiency trade-off frontier** — evidence: ch14.03-one-shot-execution-loops-and-subagents
   - More cache = higher memory, faster retrieval
   - More preprocessing = higher compute, faster runtime
   - Two systems answering equally well → cheaper is objectively better
   - Need to track Pareto frontier

## Conclusion to reach
Context efficiency is a multi-dimensional metric. Teams must measure tokens, latency, API calls, and storage lookups together to understand true cost. A system that uses more tokens but fewer API calls may be more efficient than one that uses fewer tokens with many calls.
