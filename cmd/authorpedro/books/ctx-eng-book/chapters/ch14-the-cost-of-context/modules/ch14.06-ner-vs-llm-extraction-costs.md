# NER vs LLM Extraction Costs

## The Cost Tradeoff: Traditional NER vs LLM

Choosing between traditional Named Entity Recognition (NER) and LLM-based extraction is a classic cost tradeoff. The choice impacts both upfront investment and ongoing operational costs.

## Traditional NER: High Capex, Low Opex

Traditional NER uses trained supervised or semi-supervised models (CRF, SVM, neural networks):

- **High upfront cost**: Requires labeled training data, model training pipeline, development time
- **Lower long-term cost**: Inference is fast, cheap, and deterministic once trained
- **Domain-specific strength**: Can be fine-tuned for precise performance on specialized text

Traditional NER is computationally efficient and extraction-difficult—supervised approaches significantly outperform unsupervised methods [Research Ledger: ie-ner.md]. However, they require upfront annotation effort and don't adapt to new entity types without retraining.

## LLM Extraction: Low Capex, High Opex

LLMs can perform extraction via in-context learning with few-shot examples:

- **Low upfront cost**: Just write prompts, no training required
- **Higher long-term cost**: Per-inference API costs accumulate at scale
- **Flexibility advantage**: Can extract novel entity types without retraining, handles context-dependent entity mentions

LLMs blur the line between traditional extraction and zero-shot approaches—zero-shot extraction is approaching supervised quality [Research Ledger: ie-ner.md]. The flexibility trade-off is real: you get adaptability but pay per extraction.

## The Break-Even Point

The traditional vs LLM decision depends on:

- **Volume**: At high volumes, traditional NER's one-time training cost amortizes
- **Domain stability**: Static domains benefit from trained models; volatile domains need LLM flexibility
- **Accuracy requirements**: Traditional NER can be fine-tuned for precision; LLMs are "good enough" by default

The rule of thumb: if you're extracting the same entity types from the same document types indefinitely, invest in traditional NER. If entity types change frequently or you're exploring a new domain, start with LLM and graduate to trained models when patterns stabilize.
