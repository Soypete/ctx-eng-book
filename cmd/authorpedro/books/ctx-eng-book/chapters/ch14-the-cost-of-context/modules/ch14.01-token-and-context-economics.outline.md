# Token and Context Economics

## Argument
Every decision in context engineering has a price. Token counts map directly to dollar amounts, and the cheapest reliable solution is the one that spends just enough to get the job done consistently.

## Why it matters (reliability goal)
Tie to Pragmatics pillar: context isn't free. Understanding the cost structure enables tradeoffs between price, performance, and reliability. Without this, teams overspend or underspend on context.

## Beats

1. **Token Economics** — evidence: existing prose
   - Input/output tokens map to dollar amounts
   - Context tokens double as input tokens
   - Larger context = higher per-request costs
   - Case study: 10x context bill (migrated from 4k to 128k, costs 20x)

2. **Context Windows as Budget Constraints** — evidence: existing prose
   - Context window is a budget, not just capacity
   - Truncation, compression, or fail when budget exceeded
   - Cheapest reliable approach sizes context to actual use case

3. **Model Selection as Cost Decision** — evidence: existing prose
   - Token costs vary by model (Sonnet vs Opus, GPT-4o vs Turbo)
   - Model selection is a cost decision first, capability decision second
   - Smaller context + better retrieval often beats larger context

4. **State of the Stack** — evidence: existing prose
   - Token counting standards (tiktoken, cl100k_base)
   - Model pricing APIs, prompt compression services
   - Context window specifications across providers

## Conclusion to reach
The reader should believe that context engineering requires cost-awareness. Token economics is the foundation—understand what you're spending before optimizing.
