# Cost-Aware Extraction Pipeline Design

## The Full Pipeline Cost Model

Extraction pipelines have costs at every stage: ingestion, processing, storage, and retrieval. Cost-aware design means understanding and optimizing each stage.

## Pipeline Cost Components

### Ingestion Cost
- Document loading and parsing
- Chunking strategy (smaller chunks = more embeddings = higher cost)
- Embedding generation per chunk

### Processing Cost
- NER/RE model inference (trained models) or LLM API calls
- Coreference resolution
- Ontology mapping

### Storage Cost
- Vector database storage
- Knowledge graph storage
- Index maintenance

### Retrieval Cost
- Query embedding generation
- Vector search computation
- Graph traversal (if applicable)

## Optimization Strategies

### 1. Size Chunks to Consumption
If responses typically use three supporting documents, retrieve five—not fifty. Chunk sizing directly impacts embedding costs. Smaller chunks need more embeddings; larger chunks provide less targeted retrieval.

### 2. Cache Extracted Entities
Once you've run extraction on a document, cache the results. Re-extraction on every query wastes compute. The extraction is done once; retrieval is done many times.

### 3. Route by Complexity
Simple extraction tasks (date parsing, format detection) should use rule-based methods. Complex tasks (relationship extraction from narrative text) use LLMs. Don't use a sledgehammer to crack a nut.

### 4. Parallelize When Possible
Extract from multiple documents concurrently. Extraction is embarrassingly parallel—embrace it.

### 5. Monitor the Efficiency Frontier

> Two systems answering equally well—the cheaper one is objectively better. Need to track the Pareto frontier: what's the best efficiency at each resource level? [Research Ledger: ch14.05-context-efficiency-metrics.md]

Track cost per extraction, not just accuracy. A system that achieves 95% accuracy at 1/10th the cost of a 97% accuracy system is the better engineering choice.

## The Reliability Question

The chapter's unifying question: **What is the cheapest reliable solution?**

For extraction pipelines, this means:
- What extraction accuracy does your downstream task actually require?
- Can you tolerate "good enough" with guardrails, or do you need perfection?
- What's the cost of false positives vs false negatives in your domain?

Design the pipeline to meet the required reliability at minimum cost—not maximum accuracy regardless of expense.
