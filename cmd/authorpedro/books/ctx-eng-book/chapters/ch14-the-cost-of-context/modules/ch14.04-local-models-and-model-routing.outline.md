# Local Models and Model Routing

## Argument
Local models eliminate per-token inference costs but come with capability tradeoffs. Model routing—sending simple requests to cheap models and complex ones to expensive models—is the practical application of cost-aware context engineering.

## Why it matters (reliability goal)
Tie to Pragmatics pillar: knowing when a smaller model suffices enables massive cost savings without sacrificing reliability. The key is matching task complexity to model capability.

## Beats

1. **Compute Tradeoffs: Local Models vs APIs** — evidence: existing prose
   - Local: zero per-token inference cost after hardware
   - Tradeoff: typically smaller and less capable
   - 7B might match 2022 API model, not current frontier
   - Decision: task requires frontier? Use API. Task within reach of smaller? Use local.

2. **Model Routing** — evidence: existing prose
   - Route by task complexity, not one-size-fits-all
   - Simple tasks (classification, extraction, summarization) don't need GPT-4o
   - Complex tasks (reasoning, multi-step planning) need frontier models

3. **The Cheapest Reliable Solution** — evidence: existing prose
   - Pattern across all dimensions: spend minimum necessary for required reliability
   - Know what "reliable" means: perfect accuracy? good enough with known error rate?
   - Measurement: track cost per request, reliability metrics, latency distributions
   - Compare strategies empirically, not hypothetically

## Conclusion to reach
The reader should believe that context engineering is deliberate cost-reliability tradeoffs. Every token, tool call, and loop iteration has a price—engineer to spend only what the task requires.
