# Distillation and Specialized Models

## Argument
Distillation compresses capabilities but doesn't create new ones. SLMs have improved dramatically and shift the context engineering burden—but require more scaffolding. Specialized models are only worth it for high-stakes, high-volume stable domains.

## Why it matters (reliability goal)
Tie to Efficiency pillar: SLMs can match GPT-3.5 at 10% of cost. Understanding when compression vs specialization makes sense is key to cost-optimized reliability.

## Beats

1. **Distillation** — evidence: existing prose
   - Smaller model mimics larger one—compresses, doesn't extend
   - Makes sense when: base model overqualified, clear quality thresholds, cost savings justified
   - Risk: if base model barely passes quality bar, distilled model will fail

2. **The SLM Opportunity** — evidence: ledger (Small Language Models Enterprise Viability)
   - SLMs with 7-8B params can match GPT-3.5 on domain-specific tasks, reducing inference costs 90%+ [Microsoft research](Various Microsoft/Meta model releases)
   - Benefits: local execution, no API latency, no per-token cost, data locality
   - Drawbacks: capability ceiling, need more context for similar results

3. **Specialized Models** — evidence: existing prose
   - Trained specifically for domain (medical, legal, etc.)
   - Expensive to train and maintain
   - Only worth when: domain stable, volume high, quality strict
   - For most: context engineering on general model beats training specialized

## Conclusion to reach
The reader should believe that compression (distillation) and specialization are expensive trades—not upgrades. Context engineering on general models is the default. Test SLMs on actual workload before committing.
