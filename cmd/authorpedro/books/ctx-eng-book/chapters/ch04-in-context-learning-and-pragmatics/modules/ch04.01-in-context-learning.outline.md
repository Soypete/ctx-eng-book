# In-Context Learning

## Argument
More inference by the model means less reliability. Context engineering does the inference work upfront so the model can focus on extraction rather than guessing intent.

## Why it matters (reliability goal)
Tie to Pragmatics pillar: by providing clear context (goals, constraints, examples), we reduce the model's burden to infer what the user wants.

## Beats

1. **More Inference = Less Reliability** — evidence: [Brown et al., 2020](https://arxiv.org/abs/2005.14165) + [Khattab et al., 2023](https://arxiv.org/abs/2310.05914)
   - Models infer from context; when context is ambiguous, inference produces unreliable outputs
   - Context engineering flips this: do inference work upfront, let model extract

2. **Static vs Dynamic Context** — evidence: [DSPy teleprompter pattern](research/dspy-notes.md)
   - Static (teleprompter): system prompts, instructions, few-shot examples — fixed at compile time
   - Dynamic (MCP): tool results, retrieved documents, runtime data — built at execution
   - Static for invariants, dynamic for fresh information

3. **Prompt Tuning** — evidence: [DSPy compiler optimizes prompts](research/dspy-notes.md)
   - Prompt performance is measurable and optimizable
   - What to tune: instruction wording, example selection, order effects, constraint framing

4. **Domain Expansion** — evidence: [LLMs enabling novel entity extraction](research/knowledge-graphs/ie-ner.md)
   - LLMs adapt to new entity types without retraining via in-context learning
   - Multi-lingual extraction, domain-specific entities, rapid prototyping

## Conclusion to reach
The reader should believe that the key to reliable LLM behavior is providing unambiguous, well-structured context — doing the inference work so the model doesn't have to.
