# QA-Driven SRL Benchmarks (QAMR, QA-SRL, LSOIE)

## Argument
QA-driven SRL frames extraction as question-answering rather than schema-based labeling—more natural, interpretable, and verifiable for context engineering.

## Why it matters (reliability goal)
Tie to Semantics pillar: structured extraction without predefined ontologies. QA format enables single pipeline for extraction + verification.

## Beats

1. **QA-SRL** — Question-answer driven semantic role labeling
   - Frame extraction prompts as QA: "What tool was used?" vs "Extract tool relation"
   - More natural, interpretable outputs
   - Can use same pipeline for SRL and verification

2. **QAMR** — Covers predicate-argument relationships from multiple sources
   - Includes implicit arguments and relations (previously under-resourced)
   - ~5,000 sentences, ~100,000 questions

3. **LSOIE** — Large-scale OpenIE
   - 20x more data than next largest human-annotated OIE dataset
   - Enables more robust extraction patterns

## Conclusion to reach
The reader should believe that QA-driven SRL benchmarks provide a schema-agnostic way to evaluate structured extraction—useful when your domain doesn't map to predefined ontologies.
