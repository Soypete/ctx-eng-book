# QA-Driven SRL Benchmarks (QAMR, QA-SRL, LSOIE)

## Beat: Structured Representation Through Questions

Traditional semantic role labeling (SRL) extracts predicate-argument structures from sentences—but it requires predefined ontologies and is brittle for open-domain extraction. QA-driven SRL reframes the problem: instead of asking "what role does this word play?", you ask "what would the answer be to this question about the predicate?"

This approach has natural advantages for context engineering:
- **More natural outputs**: Frame extraction prompts as QA—"What tool was used?" instead of "Extract tool relation"
- **Interpretable**: Questions make the extraction explicit and verifiable
- **Single pipeline**: Same QA pipeline can do both extraction and verification

## Benchmarks

### QA-SRL (Question-Answer Driven SRL)

**Original paper**: He, Lee, Zettlemoyer et al. (2015)[^he2015]

QA-SRL frames each predicate in a sentence as a question, with answer spans marking the semantic roles. For example:

> "The model generated a summary"
- "What did the model generate?" → "a summary" (Patient)
- "Who generated?" → "the model" (Agent)

The benchmark measures how well systems can map from question templates to correct answer spans, capturing predicate-argument structure without predefined schemas.

### QAMR (Question-Answer Meaning Representations)

**Paper**: "Crowdsourcing Question-Answer Meaning Representations"[^qamr]

QAMR extends QA-SRL by covering predicate-argument relationships from multiple sources (PropBank, NomBank, QA-SRL) and including previously under-resourced elements: implicit arguments and relations. The dataset contains ~5,000 sentences with ~100,000 questions.

Key advantage: broader coverage of argument types, making it more useful for evaluating extraction from diverse text.

### LSOIE (Large-Scale Open Information Extraction)

**Paper**: [LSOIE: Large-Scale Open Information Extraction](https://arxiv.org/abs/2101.11177)[^lsoie]
**Dataset**: [GitHub](https://github.com/jacobsolawetz/LSOIE)

LSOIE was created by converting QA-SRL 2.0 to OIE format—resulting in 20x more data than the next largest human-annotated OIE dataset. This scale matters: with more training data, models can learn more robust extraction patterns.

## Relevance to Context Engineering

For context engineering, these benchmarks matter because:

1. **Prompt design**: Frame extraction as questions, not extraction instructions
2. **Quality measurement**: Use benchmark scores to evaluate your extraction pipeline
3. **Verification**: Same question-answer format can verify extracted context

## State of the Stack

- **Extraction Frameworks**: Most LLM frameworks support structured extraction via function calling
- **Benchmark Implementations**: Available in research repositories, not production-ready libraries
- **Gap**: No standard production tool for QA-driven SRL evaluation

## Questions to Ask Before Adoption

1. Do you need open-domain extraction, or would schema-based SRL work for your domain?
2. Is your domain covered by existing benchmarks, or do you need custom QA pairs?
3. Can you use the QA format for both extraction AND verification in your pipeline?
