# Retrieval and Tool Evaluation

## Argument
Context quality determines output quality. If retrieval returns irrelevant documents, the model can't produce good answers. Context precision—not IR precision—measures how much retrieved context was actually useful.

## Why it matters (reliability goal)
Tie to Pragmatics pillar: retrieval is the mechanism for context assembly. Poor retrieval = poor context = poor outputs. Must measure what matters.

## Beats

1. **Retrieval Accuracy** — evidence: ledger (Context Precision, Hydration Coverage)
   - Recall: of documents that would make answer correct, how many retrieved?
   - Precision: of documents retrieved, how many actually relevant?
   - Context Precision = Useful Context / Retrieved Context (not IR precision)
   - Too much irrelevant context → cost, latency, attention competition, hallucination risk
   - Hydration Coverage: of required context, how much successfully retrieved?

2. **The Eval Pipeline** — evidence: existing prose
   - Unit tests → deterministic checks on components
   - Integration tests → composition of components with fixed inputs
   - Evals → AI behavior judgment (LLM-as-judge, golden datasets)

## Conclusion to reach
The reader should believe that retrieval evaluation is distinct from traditional IR metrics—context precision measures usefulness, not just relevance.
