# Mounts, Namespaces, and Isolation

## Argument
Context sources should mount into a single namespace, like UNIX filesystems. AI systems need namespace isolation between tenants—scoped retrieval, limited memory, constrained tools, bounded permissions.

## Why it matters (reliability goal)
Enable multi-tenancy without leakage; prevent cascade failures; enforce authorization at the filesystem level.

## Beats

1. **Mounts: Different Stores into One Namespace** — evidence: knowledge graph as semantic router [kg-quality-metrics-notes](research/kg-quality-metrics-notes.md)
   - /user/, /session/, /memory/, /tools/, /ontology/, /secrets/
   - Different backends with different semantics, same file-like interface
   - Retrieval navigates namespace, reads from relevant mounts

2. **Namespaces: Isolation Between Tenants** — evidence: capability-based access control for AI agents [Brandstetter et al., 2024](https://arxiv.org/abs/2412.10891)
   - RBAC fails for dynamic, multi-step agent actions; capability-based provides fine-grained, revocable permissions
   - Scoped retrieval, limited memory, constrained tools, bounded permissions

3. **Authorization Failure Modes** — evidence: agent authorization research [Rashidi, 2026](https://arxiv.org/abs/2607.05743)
   - Policy-enforcement failure rates 69-98%; isolation papers don't re-evaluate under adversarial settings
   - Namespace-level enforcement needed, not application-level checks

4. **Context-to-Execution Integrity** — evidence: Santos-Grueiro [2026](https://arxiv.org/abs/2607.06000)
   - Language-model agents read attacker-writable context; tool execution needs separate authority check
   - Protected sink fields, sink-interpreted payloads, invocation events require isolation

5. **Process Isolation: Agents Can't Crash the System** — evidence: cryptographic confinement [Qin et al., 2026](https://arxiv.org/abs/2607.04613)
   - Confinement guaranteed as invariant of execution architecture, not probabilistic training outcome
   - Tool failures isolated, context corruption contained, cascade failures prevented

## Conclusion to reach
The reader should believe that context mounts and namespaces provide the isolation layer that makes multi-tenancy possible, preventing leakage and containing failures.
