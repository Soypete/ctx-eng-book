# Small Composable Systems

## Argument
AI systems face a complexity problem—accumulating components (retrievers, memory stores, tool servers, knowledge graphs, authorization layers) that are harder to debug, test, and reason about. The UNIX philosophy—small composable systems with clear interfaces—provides the reliability model.

## Why it matters (reliability goal)
Reduce system complexity through composition over monoliths, following established systems principles that have scaled for decades.

## Beats

1. **The UNIX Philosophy** — evidence: original UNIX principles (do one thing well, work together, text streams as universal interface)
   - Three principles from the original paper: focus, composition, universal interface
   - Reliability engineering, not aesthetics

2. **Small Components in AI** — evidence: DSPy modules as composable scaffolding [Khattab et al., 2023](https://arxiv.org/abs/2310.01428)
   - Focused retrieval systems, dedicated tool services, discrete memory systems, specialized model harnesses
   - Each component testable, replaceable, composable

3. **The Scaffolding Tax** — evidence: AI infrastructure research (2024) [The Scaffolding Tax](research/scaffolding-tax-ai-utah-talk.md)
   - Current AI systems pay a tax because we ask transformers to perform data platform tasks
   - Transformers decide what information future tasks will require before those tasks exist
   - Information loss in compaction steps is irreversible

4. **Context Assembly Pipelines** — evidence: context-assembly-pipeline-patterns [Context Assembly](research/context-assembly-pipeline-patterns.md)
   - Query pipeline that assembles context from multiple sources before inference
   - Each stage independent, swappable

## Conclusion to reach
The reader should believe that AI systems should follow UNIX principles—small tools, clear interfaces, composition over monoliths—to reduce complexity and improve reliability.
