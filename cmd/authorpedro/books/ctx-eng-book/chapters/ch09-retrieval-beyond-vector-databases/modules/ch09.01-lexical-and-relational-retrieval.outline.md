# Lexical and Relational Retrieval

## Argument
Vector databases alone cannot answer precise lookup questions—the system needs keyword search (BM25), exact matching, and relational queries to retrieve specific facts, not just semantically similar content.

## Why it matters
Semantic similarity is the wrong retrieval primitive for precise lookups. A system needing "the user's billing tier" or "which tools this agent has access to" cannot rely on vector similarity. These are exact-match queries that BM25 and relational databases handle correctly.

## Beats

1. **The Limits of Semantic Similarity** — evidence: existing prose
   - Vector search answers "which documents are semantically similar?"
   - Cannot answer "what is the user's billing tier?" or exact ID lookups
   - Legal system example: "breach of contract" vs data breach vs ethical violation

2. **BM25 and Keyword Search** — evidence: existing prose
   - BM25 (Lucene, Elasticsearch, OpenSearch) scores by TF-IDF and document length
   - Exact matching: "Order-2024-001", "GDPR compliance"
   - Respects domain-specific terminology

3. **The Hybrid Pattern** — evidence: hybrid-retrieval-architectures (line 67-73)
   - Run keyword and vector queries in parallel
   - Combine results, rerank by weighted scoring
   - Exact-match precision with semantic generalization

4. **Relational Queries for Structured State** — evidence: GAP
   - Structured queries: user preferences, permissions, IDs
   - Not documents—precise values from relational stores
   - Essential for agent authorization and state

## Conclusion to reach
Reliable retrieval requires BM25 and relational queries alongside vector search. Each primitive serves different query types. The vector database is one tool in the retrieval toolbox.
