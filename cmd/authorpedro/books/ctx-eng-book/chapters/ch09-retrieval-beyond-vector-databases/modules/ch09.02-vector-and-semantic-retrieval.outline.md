# Vector and Semantic Retrieval

## Argument
Semantic indexing structures indexed representations to support precise retrieval—embedding with metadata filters, hierarchical distillation, and multi-granularity storage that pure vector search cannot express.

## Why it matters
A vector index over an entire corpus cannot filter by product version, user role, or issue category. Semantic indexing adds structure to embeddings, enabling filtered semantic search that retrieves the right content for the right context.

## Beats

1. **Semantic Indexing Beyond Embeddings** — evidence: existing prose
   - Embed article sections, FAQ answers, procedure steps as separate chunks
   - Index with metadata: product version, issue category, user role, severity
   - Query includes filters; vector search operates on filtered subset

2. **Knowledge Stores** — evidence: existing prose
   - Structured metadata alongside embeddings
   - Structured filtering alongside semantic search
   - Query interfaces that combine both

3. **Hierarchical Distillation** — evidence: Mem0 benchmark claims
   - Storing user interactions at multiple granularity levels (user, session, message)
   - Query across all levels for context
   - Mem0 benchmark scores (LoCoMo 92.5, LongMemEval 94.4) — but note benchmark variability

4. **Design Index Schema Before Embedding Strategy** — evidence: GAP
   - Decide metadata filters first (user type, time period, document type)
   - Build vector index to support those filters
   - Retrieval query precision limited by index design

## Conclusion to reach
Design your indexing schema before your embedding strategy. Semantic indexing—embedding with structured metadata and filtering—is essential for production retrieval systems.
