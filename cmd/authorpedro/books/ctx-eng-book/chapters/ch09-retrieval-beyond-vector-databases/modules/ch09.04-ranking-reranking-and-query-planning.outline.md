# Ranking, Reranking, and Query Planning

## Argument
Reliable retrieval requires query planning—parsing each query into components, routing to appropriate primitives, combining results. This is database engineering with a language model as the consumer.

## Why it matters
A retrieval system that uses only one primitive will fail for queries requiring others. Query planning ensures each query component reaches the right retrieval primitive. The architecture is straightforward: parse, route, combine, return.

## Beats

1. **The Query Planning Pattern** — evidence: existing prose
   - Parse query into structured filters, keywords, semantic components
   - Route each component to appropriate primitive
   - Combine results, score by relevance, return final ranked list
